# 15 · 多轮 Agent 工具结果回填

> 本文回答:AI 操作助手如何把受治理工具结果以 `tool_call_id` 回填模型，继续下一轮规划，并在预算、异常和超时时安全收口。
> 状态:定稿 v1

## 范围

已实现的最小闭环位于 `src/fulcrum/adapters/assistant/agent.py`:

- 模型返回 `tool_calls` 后，助手先按既有 RBAC、读写分流和工具返回闸门执行或处置；每一条结果都以 `role: tool`、原始 `tool_call_id`、工具名和受处置内容追加到规范消息序列。
- 下一模型轮收到完整的 `assistant.tool_calls` 与对应 `tool` 消息，因此只能依据受治理结果继续规划。写类工具仍仅生成提案，确认、审批和撤销链路不变。
- 单次会话默认限制为 8 个模型规划轮、8 次工具调用、12,000 个估算上下文令牌和 60 秒墙钟时间。令牌值由规范消息序列化字符数按保守规则估算，原因是当前三种模型传输协议没有统一 usage 返回。
- 预算耗尽、模型或工具超时、模型或工具异常、越权工具调用都会停止后续模型/工具调用；出口闸门异常则拦截未审答复。所有这些路径均在既有 `ASSISTANT_CHAT` hash-chain 审计中记录终止原因、轮数、工具调用数和估算令牌数。

## 非范围与限制

- 本期不改变单轮成功路径，也不改变高危写操作的人审、策略和审批要求。
- 预算不等同于上游账单 token；后续若所有模型协议均返回可靠 usage，可替换为精确计量。
- 流式路径在最终出口闸门判定前仍可能已发送文本增量；最终 `done` 事件仍以出口闸门处置结果为准。这是现有流式协议的限制，不在本优先级修改范围。

## 验证

定向测试使用 fake model/client 和无害内存工具，不访问外部服务，覆盖:

- 原始 `tool_call_id` 回填后触发下一轮规划。
- 令牌预算耗尽时模型不被调用且会话审计收口。
- 模型超时、受治理工具或出口闸门异常时停止后续规划或拦截答复，并留审计证据。
