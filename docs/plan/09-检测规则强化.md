# 09 · 检测规则强化(Rule Hardening)

> 目标:把当前"很烂"的规则层提到**专业/标准**水平。方法论:**先归一化/解码,再匹配**(OWASP LLM01 官方缓解 + Unicode TR39 标准),参考同行实现。
> 测量驱动:每改一步都跑冻结的 `samples/eval/corpus`(v1.0.0)量召回/FPR 变化,**只做可泛化的标准防御,不针对样本 ID 硬编码**(防过拟合)。
> 注意:本阶段**只优化规则(确定性、可解释)**;神经/LLM 语义层是后续 P0(见 [08 §8] 与本文件 §6)。

## 1. 现状与根因(为什么烂)
- 当前检测是**纯关键词正则**(`keyword_rules` + `argrisk`),**匹配前不归一化**:同形字/零宽/双向/全角/leetspeak/嵌套编码全部绕过。
- 输入层在硬集召回仅 ~21%;竞品神经分类器 84–99%(但 FPR 47–94%,见 `benchmarks/scorecard.md`)。
- 工具层正则有精确漏洞:`certutil -decode`、`reg save`、`${IFS}`、双重编码穿越、IP 进制混淆。
- 两条 FP:把"科普 /etc/passwd""问 API key 是什么"当攻击(缺意图区分)。

## 2. 参考的同行/标准
| 来源 | 借鉴点 |
|---|---|
| **OWASP LLM01:2025** 缓解 | "输入归一化 + 分隔可信/不可信内容";结构化注入特征 |
| **Unicode UTS#39**(Confusables/Security) | 同形字折叠(skeleton)、混合脚本检测 |
| **Unicode NFKC** | 全角→半角、兼容分解 |
| **Vigil** | 用 **YARA 签名**表达提示注入特征(结构化、可维护) |
| **ProtectAI LLM Guard** | BanSubstrings / Regex / Secrets 扫描器分层 |
| **Microsoft Presidio** | PII 识别的**识别器 + 上下文增强**范式(替我们手搓 PII 正则) |
| **PayloadsAllTheThings / PortSwigger** | SSRF IP 进制归一、路径穿越编码变体 |
| **LOLBAS / GTFOBins / Sigma** | LOLBins 命令签名(certutil/bitsadmin/…)、反弹 shell 范式 |
| **CWE-1427 / MITRE ATLAS T0051** | 注入分类与命名口径 |

## 3. 阶段计划(按杠杆排序,逐步可测)

### P1 归一化预处理器(单点最高杠杆)— `core` 新增 `normalize()`
匹配前对文本做(保留原文供审计,只在"匹配副本"上做):
1. **NFKC** 归一(全角→半角、兼容字符)。
2. **剥不可见控制符**:零宽 U+200B/200C/200D/FEFF/00AD、双向 U+202A–202E/2066–2069、Unicode Tag 块 U+E0000–E007F、变体选择符。
3. **同形字折叠**:Cyrillic/Greek 常见混淆字 → 拉丁 skeleton(UTS#39 思路,内置高频映射表)。
4. **de-leet**(谨慎、仅辅助副本):0→o 1→i 3→e 4→a 5→s 7→t @→a $→s。
5. **递归解码再扫(限深)**:base64 / hex / URL-编码 / ROT13 抽取候选块解码,追加进扫描缓冲,递归 ≤2 层。
> 预计救回:`unicode.*`(全角/同形/零宽/双向)+ `encoding.*`(嵌套 base64/hex/rot13/leet)≈ 12 条。

### P2 注入/越狱结构化签名(参考 Vigil/OWASP)
- **伪边界/角色注入**:`</system>`、`</user>`、`[/INST]`、`<|im_end|>`、行内 `tool_result:`/`assistant:`/`system:`。
- **配置块注入**:`<interaction-config>`、`allowed-modes`、`blocked-strings`。
- **拒绝抑制**:`不要(说|加)…(无法|不能|抱歉|免责|政策)`、`don't (apologize|refuse)`、`no disclaimer`。
- **前缀诱导**:`以"…"开头`、`start (your )?(answer|reply) with`、`begin with "Sure`。
- **载荷分片**:变量赋值 + 拼接(`a+b+c`、`设 a=… b=…`)。
- **权威伪装**:`开发者模式|平台团队|系统覆盖|审计豁免|developer mode|system override`。
- **人格越狱**:`DAN|AIM|DevMode|无限制|不受任何限制|越狱`。
- **多语种**:对上述意图补英文模式(攻击常中英混写)。

### P3 argrisk 精确补洞(参考 PayloadsAllTheThings/LOLBAS)
- **IP 归一**:host 解析十进制/十六进制/八进制/IPv4-mapped-IPv6 → 32/128 位整数 → 比 CIDR(loopback、169.254/16、RFC1918、**阿里云 100.100.100.200**)+ `not is_global`。
- **路径**:判定前递归 URL 解码(救双重编码 `%252e`)。
- **命令**:补 `certutil .*-decode`、`reg\s+save`、`${IFS}`/`$IFS`、brace 展开、`-enc`/base64 解码后再匹配;破坏性动作(delete/drop + 通配/递归)。

### P4 策略补齐(YAML)
- gov_demo 移植 default 的 `block-nonwhitelist-domain`(http.request);新增 `block-ssrf-internal`(url_is_internal/is_raw_ip)、`block-destructive`(*.delete 通配/递归)。

### P5 降 FPR(意图区分)
- **疑问/科普语气降权**:`什么是X|X是什么|如何防范|怎么理解|解释一下|科普` + 攻击词 → 不计高危(救 `neg-01`/`neg-08` 等)。
- 与硬负例集回归绑定,确保召回升的同时 FPR 不升。

### P6 神经/LLM 语义层
- 规则补不到的语义注入 → 神经/LLM 兜底,规则做"快速精准前置",分数融合。**两条路线均已实跑对标**:
  - ❌ **专用分类器**(`detector/ml_classifier`,protectai):对中文政务良性过度告警,FPR 47% 阈值不可调,无安全操作点(`benchmarks/p6-fusion-tuning.md`)。
  - ✅ **LLM-judge**(`detector/llm_judge`,中文原生 MiMo):FPR 0.0%,融合保 FPR 补召回(`benchmarks/p6-llm-judge.md`)。**选定方案**。

## 4. 验收(每阶段必测)
- 跑 `python -m fulcrum.eval --dataset samples/eval/corpus --policy default`;记录召回/FPR/分桶/覆盖矩阵 delta。
- **守门**:FPR 不升过 10%;292 单测 + ruff 全绿;新行为补单测。
- 目标轨迹:输入层召回 21% → P1 后 ≥40% → P2 后 ≥60%;FPR 维持 ≤10%。
