# 枢衡 Fulcrum · AI 操作助手「工具表渐进式披露」(可持续扩展)

> 本文回答:随着队友按「注册即接入」不断加操作,助手的**工具表怎么不把上下文撑爆**——抄 Claude Code 的**渐进式披露(progressive disclosure)**,让每轮上下文开销与操作总数**解耦**。
> 状态:**📐 方案 + 落地(Phase 1)**。延续 [11-AI操作助手·真Agent](11-AI操作助手·真Agent实现方案.md);硬约定见 [arch/01 §5.1](../arch/01-后端骨架与扩展规范.md)。
> 安全红线不变:前端门禁只是体验,真授权后端强制;`search` 只在**已可见(visible_for)**的工具里检索,不绕 RBAC。

---

## 0. 问题:当前是 O(操作总数) per turn

现状(`agent.py`):每轮把当前角色**可见的全部工具**的完整 function schema 塞进 `self._turn(messages, specs)`。实测开销:

| 操作数 | 每轮工具定义开销 | |
|---|---|---|
| 32(现在) | ~3.0k token | 尚可 |
| 100 | ~9.3k token | 肉疼 |
| 200 | ~18.6k token | 撑爆;且**每轮重付**、与对话内容无关 |

对话历史那条轴已由 `ConversationStore` + summarizer 接住;**工具表是没堵的口子**。队友每加一个 `@operation`,所有人每轮都多付一份 schema——不可持续。

## 1. 业界做法

- **Codex(OpenAI)= 极简工具**:基本一个 `shell` + `apply_patch`,模型用命令行自己组合。零工具表开销,但**无结构化 RBAC/审计**——与我们的 propose-confirm-undo + 按操作鉴权相悖,**不抄**。
- **Claude Code = 渐进式披露**:一小撮常驻核心工具始终在场;其余工具**只露名字**,schema 不进上下文,模型要用时按需检索取回(`ToolSearch`)。技能、子代理同理(只加载摘要,用时展开)。**抄这个**——我们的操作注册表正好适配。

## 2. 设计

### 2.1 分层工具表
- **Tier-0 常驻**(`_CORE_TOOLS`,4 个):`navigate`、`get_overview_stats`、`list_events`、`list_users` —— 跨切面 + 最高频。仍受 `visible_for` 过滤(无权则不出现)。
- **元工具 `search_operations(query[, domain])`**:常驻。按关键词/领域在**当前角色可见**的操作里检索,返回匹配操作的 名称/用途,并把它们**加载**进会话——之后即可直接调用。
- **Tier-1 按需**:其余操作不进每轮 specs;经一次 `search` 加载后才进。

每轮 specs = `Tier-0 ∩ 可见` + `本会话已 search 加载的` + `search_operations`。**与操作总数解耦**,恒为 O(核心 + 已加载)。

### 2.2 领域自动派生(零维护)
不给每个操作手填 domain,而是从其首个权限点前缀**自动派生**:`users.view→users`、`settings.manage→settings`、`dept.manage→dept`……无 requires(如 `navigate`)→ `general`。**队友加操作零额外动作**,domain 白来。

### 2.3 低工具数自动旁路
角色可见工具数 ≤ `_PROGRESSIVE_THRESHOLD`(16)时,**退回一次性全发**(无检索往返)——小角色/小部署不付渐进式的复杂度。超过才启用渐进式。

### 2.4 流程
```
可见工具数 ≤16  → 全发(现状,零改动语义)
可见工具数 >16  → 系统提示加一句「工具按需加载,用 search_operations 找」
                 每轮只发 核心+已加载+search;
                 模型想做的事没现成工具 → 调 search_operations("改部门")
                 → 命中的操作 schema 下一轮注入 → 模型直接调它
```

## 3. 兼容性
- **操作 handler 一行不动**;`@operation` 约定不变,domain 自动派生。
- 执行/RBAC 不变:`by_name` 仍是全部可见工具,纵深复校照旧;模型经 function-calling 物理上无法调用未加载工具,故不会越界。
- 写操作的提案-确认-撤销链路、三道吃狗粮闸门**完全不受影响**。

## 4. 实现(Phase 1,本次)
1. `core/operations.py`:`AssistantTool.domain` 计算属性(requires 前缀派生);`OperationRegistry.search(principal, query, domain, limit)`。
2. `agent.py`:`_CORE_TOOLS` / 阈值 / `search_operations` spec / 系统提示注入 / 每轮 `_specs_for_turn` / `_handle_search`;`run` 与 `run_stream` 双路接入。
3. 测试:search→加载→调用 全链;核心工具恒在;低工具数旁路;RBAC 不被 search 绕过。
