> 本文回答:**枢衡要管理哪些智能体安全问题,每类问题通过什么能力实现。**

## 1. 一句话说明

枢衡不是业务智能体,也不是基座大模型;它是**守护业务智能体的安全中台 / 安全网关**。

对外,枢衡接入被保护智能体调用大模型、调用工具和执行高危动作的关键路径;对内,枢衡可以使用规则、小模型、大模型和安全分析 Agent / workflow 来完成风险识别、策略判定、供应链扫描、审计溯源和评测裁判。

```text
业务智能体负责干活。
枢衡负责判断它干得安不安全。
```

---

## 2. 枢衡不管什么

先明确边界,避免把项目做散:

- 不接管企业全部网络流量。
- 不替代政务办公、知识问答、运维助手等业务智能体。
- 不自研基座大模型。
- 不重做完整 OA、流程系统、知识库系统或运维平台。
- 不承诺对绕过枢衡的调用凭空强制拦截。

枢衡管理的是**智能体相关的关键安全边界**:

```text
智能体调用大模型
智能体读取外部内容
智能体调用工具
智能体执行高危动作
智能体接入插件 / Skill / MCP 工具
智能体运行过程的审计与评测
```

## 3. 总体安全问题地图

| 安全问题 | 典型风险 | 枢衡要做到什么 | 主要实现能力 |
|---|---|---|---|
| 输入侧污染 | 提示注入、间接指令污染、越狱、知识投毒 | 识别不可信输入,判断其是否影响模型决策或工具调用 | LLM 代理、输入检测、来源标注、证据化归因、风险分级 |
| 模型交互风险 | 模型被诱导偏离任务、输出危险计划、生成高危 tool call | 在模型请求和响应处做安全检查,拦截危险意图 | LLM API 网关、输出检测、工具调用意图解析、策略判定 |
| 工具调用风险 | 越权读写文件、执行命令、外联泄露、调用敏感接口 | 在工具执行前判断是否允许、审批、净化或阻断 | Tool/MCP 代理、工具风险评分、策略引擎、分级处置 |
| 执行环境风险 | 命令失控、文件越界、网络外联、资源滥用 | 把高危动作放进受控边界执行,限制影响范围 | 沙箱执行器、路径白名单、网络白名单、超时与资源限制 |
| 供应链风险 | 插件、脚本、Skill、MCP 工具夹带后门或恶意指令 | 接入前扫描组件风险,给出评级和准入建议 | 供应链扫描器、manifest 分析、依赖分析、静态/动态分析 Agent |
| 数据泄露风险 | 敏感信息被读出、写入外部文件、通过 HTTP 发出 | 识别敏感数据流向,阻断未授权外发 | 数据识别、DLP 规则、工具参数检查、外联管控、审计证据 |
| 任务链异常 | 多步组合后形成危险行为,单步看不明显 | 分析连续动作是否偏离用户目标或形成攻击链 | 任务链/轨迹分析、会话级风险累积、异常序列检测 |
| 审计不可追溯 | 出事后不知道谁触发、模型为何调用、系统为何放行 | 记录关键证据,支持复盘、定位和责任追踪 | 审计事件、hash-chain、防篡改日志、来源归因链 |
| 效果不可证明 | 只声称安全,没有量化指标和可复现证据 | 用样例和指标证明攻击成功率下降、误伤可控 | 评测引擎、样例集、ASR/FPR/Utility/溯源命中率 |

## 4. 关键安全问题与实现路径

### 4.1 输入侧污染

**问题是什么**

智能体会读取用户输入、网页、文档、知识库检索结果、历史记忆、工具返回值。这些内容里可能夹带恶意指令,诱导模型忽略原任务、泄露数据或调用危险工具。

**要管理的风险**

- 直接提示注入:用户直接要求模型忽略规则、越权操作。
- 间接提示注入:网页、文档、工具返回值中隐藏恶意指令。
- 越狱诱导:诱导模型绕过安全约束。
- 知识投毒:污染知识库或记忆,长期影响决策。

**实现路径**

- 在 LLM 请求进入模型前,通过 LLM 代理截获上下文。
- 对每段输入标注来源和信任级别,例如用户、网页、文档、检索、记忆、工具返回。
- 使用规则、小模型、相似度、LLM judge 等方法识别注入和越狱风险。
- 对可疑输入打风险分,并把来源信息写入后续工具调用判定和审计链。

**输出结果**

- 风险标签:正常 / 可疑 / 高危。
- 输入来源记录。
- 可用于策略判断的风险分数。
- 可用于审计的证据片段。

---

### 4.2 模型交互风险

**问题是什么**

大模型负责推理和生成,但它可能被污染输入诱导,产生危险计划或工具调用意图。

**要管理的风险**

- 模型偏离用户原始任务。
- 模型输出泄露敏感内容。
- 模型生成危险 tool call,例如读取敏感文件、执行命令、外发数据。
- 模型被不可信上下文驱动做出高危决策。

**实现路径**

- 让业务智能体调用大模型时先经过枢衡 LLM API 网关。
- 请求前检查输入上下文;响应后检查模型输出和工具调用意图。
- 将工具调用意图转成结构化对象,交给策略引擎判断。
- 对模型输出保留审计摘要和必要哈希,避免日志本身泄露敏感内容。

**输出结果**

- 模型请求/响应审计事件。
- 工具调用意图。
- 任务偏离或危险输出告警。
- 后续工具管控所需的上下文证据。

---

### 4.3 工具调用风险

**问题是什么**

智能体真正造成事故,通常不是因为它说了什么,而是因为它调用工具做了什么。文件、命令、浏览器、HTTP、数据库、邮件等工具都可能带来高风险。

**要管理的风险**

- 未授权读取、写入或删除文件。
- 执行危险命令。
- 访问恶意网址或向外部接口发送敏感数据。
- 调用超出任务范围的数据库、业务接口或 MCP 工具。
- 被不可信内容诱导执行高危动作。

**实现路径**

- 标准工具优先通过 MCP / Tool 代理接入枢衡。
- 非标准工具通过工具适配器接入统一管控。
- 工具调用前解析工具名、参数、目标资源、来源证据和会话上下文。
- 策略引擎按风险分级输出 `allow / sanitize / approve / block`。
- 高危动作放入沙箱执行器,即使放行也限制影响范围。

**输出结果**

- 工具风险评分。
- 策略决策。
- 审批请求或阻断原因。
- 工具执行审计事件。

---

### 4.4 执行环境风险

**问题是什么**

即使工具调用被判定允许,真实执行时仍可能产生副作用,例如命令失控、路径越界、网络外联、资源耗尽。

**要管理的风险**

- 命令执行破坏本机或容器环境。
- 文件读写越过授权目录。
- 工具运行时访问外网或内网敏感地址。
- 长时间运行、占满 CPU/内存/磁盘。

**实现路径**

- 高危工具通过沙箱执行器运行。
- 限制工作目录、可写路径、网络访问、执行时间和资源用量。
- 对执行前参数、执行后结果和关键副作用做审计。
- 对无法隔离的动作提高风险等级或要求人工审批。

**输出结果**

- 执行前后审计记录。
- 沙箱结果摘要。
- 超时、拒绝、越界、外联等安全事件。

---

### 4.5 供应链风险

**问题是什么**

智能体常通过插件、脚本、Skill、MCP 工具扩展能力。这些组件可能夹带恶意描述、危险权限、后门逻辑或隐蔽外联。

**要管理的风险**

- MCP tool description 中藏提示注入。
- 插件声明权限过大。
- 脚本或二进制包含可疑 API、外联地址或持久化行为。
- Skill 执行时下载未知代码或访问敏感路径。
- 新组件注册后改变工具行为。

**实现路径**

- 接入新组件前先做供应链扫描。
- 检查 manifest、权限声明、工具描述、依赖、外联地址和危险 API。
- 对脚本和可执行文件可编排静态分析、沙箱动态分析和 LLM 风险总结。
- 输出安全评级和准入建议:允许、限制、审批、拒绝。

**输出结果**

- 组件安全评级。
- 风险原因和证据。
- 是否允许注册或启用。
- 供应链扫描审计记录。

---

### 4.6 数据泄露风险

**问题是什么**

智能体可能在读取、生成、写文件、发请求或调用工具时泄露敏感数据。

**要管理的风险**

- 读取不该读的文件。
- 把敏感数据写到外部文件或日志。
- 通过 HTTP、邮件、浏览器、API 调用外发敏感内容。
- 工具返回值中包含敏感信息后被继续传播。

**实现路径**

- 对输入、工具参数、工具返回和输出做敏感信息识别。
- 对高风险外发动作做目的地和内容检查。
- 对不可信来源驱动的外发动作默认收紧策略。
- 对审计日志做脱敏或哈希存证,避免审计系统自身泄露。

**输出结果**

- 敏感数据命中记录。
- 外发阻断或审批事件。
- 脱敏审计证据。

---

### 4.7 任务链异常

**问题是什么**

有些攻击不是单步危险,而是多个普通动作组合后形成危险链路。例如先读取文件,再压缩,再通过 HTTP 发出。

**要管理的风险**

- 多步动作组合造成数据泄露。
- 智能体任务逐步偏离用户目标。
- 短时间内频繁访问敏感资源或外部地址。
- 低风险动作累积成高风险行为。

**实现路径**

- 以会话为单位记录工具调用轨迹。
- 定义异常任务链模式,例如 `read_sensitive -> http.request`。
- 根据时间窗口、动作序列、来源证据和风险累计值调整处置。
- 对异常链触发审批、阻断或告警。

**输出结果**

- 会话级风险分。
- 异常任务链告警。
- 触发策略的动作序列证据。

---

### 4.8 审计不可追溯

**问题是什么**

安全系统不能只在当时拦截,还要在事后解释:为什么拦、为什么放、是谁触发、证据在哪里。

**要管理的风险**

- 出事后无法复盘。
- 无法证明某次攻击是否被阻断。
- 无法追踪危险工具调用来自哪段输入。
- 审计日志被修改或缺关键字段。

**实现路径**

- 对模型请求、输入来源、工具调用、策略决策、审批、执行结果写审计事件。
- 使用 append-only 与 hash-chain 保护关键审计链。
- 通过来源标注与证据化归因连接“输入源 -> 模型决策 -> 工具调用 -> 处置结果”。
- 对审计查询提供 event_id / session_id / trace_id 等索引。

**输出结果**

- 防篡改审计链。
- 来源归因链。
- 风险事件详情。
- 可复盘、可展示的证据。

---

### 4.9 效果不可证明

**问题是什么**

安全方案如果没有指标,就只能靠口头描述。比赛和政企落地都需要证明“防住了多少、误伤多少、代价多大”。

**要管理的风险**

- 无法量化攻击成功率下降。
- 无法说明误报、漏报和正常任务影响。
- 无法复现实验结果。
- 无法证明审计和溯源完整性。

**实现路径**

- 建立攻击样例集、正常任务集、供应链样例集。
- 每条样例标注攻击类型、输入来源、预期处置、成功条件和真实注入源。
- 通过评测引擎对比 Baseline 与 Fulcrum。
- 输出 ASR、FPR、Utility、阻断率、审计完整率、溯源命中率等核心指标。

**输出结果**

- 评测报告。
- 逐样例判定明细。
- 可复现实验命令。
- 指标趋势和消融结果。

## 5. 枢衡内部可以有哪些安全分析 Agent

枢衡整体定位是安全中台,但内部可以使用 Agent / workflow 来完成复杂安全分析。

| 内部 Agent / Workflow | 负责什么 | 可调用的工具 |
|---|---|---|
| 输入风险分析 Agent | 判断输入是否包含注入、越狱、投毒等风险 | 规则、小模型、LLM judge、相似度库 |
| 工具调用审计 Agent | 分析工具调用是否越权、是否偏离任务目标 | 策略引擎、来源归因、轨迹分析 |
| 供应链扫描 Agent | 分析插件、Skill、MCP、脚本、可执行文件风险 | manifest parser、依赖分析、Semgrep、YARA、capa、沙箱 |
| 恶意文件分析 Agent | 对上传或接入的可疑文件做静态/动态分析 | strings、PE parser、Ghidra/IDA 结果、沙箱报告 |
| 审计溯源 Agent | 将风险事件串成可解释证据链 | 审计库、trace 查询、归因候选 |
| 评测裁判 Agent | 判断攻击是否成功、处置是否正确 | 样例标注、裁定器、LLM judge |

注意:这些 Agent 是枢衡内部的安全分析能力,不是对外的业务智能体。对外仍应统一表述为**智能体安全中台 / 安全网关**。

## 6. 实现能力分层

不同安全问题不一定都靠大模型解决。枢衡应采用分层防护:

| 层级 | 适合解决的问题 | 特点 |
|---|---|---|
| 规则与静态策略 | 路径白名单、危险命令、敏感外联、权限声明 | 快、稳定、可解释 |
| 小模型 / 分类器 | 提示注入、越狱、文本风险分类 | 延迟较低,适合在线拦截 |
| 大模型 / LLM judge | 复杂语义判断、归因解释、报告总结 | 解释力强,但成本和延迟更高 |
| 工具与沙箱 | 文件分析、命令执行、浏览器访问、恶意样本运行 | 能获得真实行为证据 |
| 审计与评测 | 证据留存、攻击复现、指标出分 | 支撑可信交付 |

原则:

- 能用确定性规则解决的,不要先交给大模型。
- 高危动作不能只靠模型判断,必须有策略和执行边界。
- 大模型适合做语义分析和解释,不应成为唯一安全边界。
- 所有关键判断都应留下证据和可复现记录。

## 7. 与四个赛题目标的关系

| 赛题目标 | 本文对应安全问题 | 枢衡主要能力 |
|---|---|---|
| 目标 1:复杂输入链路攻击识别与风险评估 | 输入侧污染、模型交互风险、知识投毒 | LLM 代理、输入检测、来源标注、风险分级 |
| 目标 2:工具调用和任务执行安全约束 | 工具调用风险、执行环境风险、数据泄露、任务链异常 | Tool/MCP 代理、策略引擎、审批阻断、沙箱执行器 |
| 目标 3:插件、Skill 与脚本生态供应链安全 | 供应链风险、恶意组件、可疑文件 | 供应链扫描 Agent、静态分析、动态沙箱、评级准入 |
| 目标 4:安全评测与审计溯源 | 审计不可追溯、效果不可证明 | 审计链、来源归因、评测引擎、指标报告 |

## 8. 后续文档衔接

本文只回答“管什么安全问题、靠什么实现”。后续应由不同文档继续展开:

- 架构设计:放入 `docs/arch/`,说明组件边界、接口契约和数据流。
- 评测设计:放入 `docs/eval/`,说明指标、样例 schema、裁定器和复现方式。
- 样例管理:放入 `samples/README.md` 或专门文档,说明脱敏、风险级别和入库规则。
- 数据管理:放入 `data/README.md` 或专门文档,说明数据来源、字段、标注和隐私边界。
