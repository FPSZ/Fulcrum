# 14 · 分级可配置安全 · 按区域自定义检测

> 本文回答什么问题：如何按输入、工具和出口等闸门配置检测强度，在召回、延迟和资源成本之间做可解释的取舍。
> 状态：候选方案/专项实验记录（2026-06）；文中 Judge 全量与级联数据不代表当前 `origin/dev` 主基线，也未表示对应开放 PR 已合并。
> 当前确定性主结果见 [`docs/eval/results/latest.json`](../eval/results/latest.json)；开放 PR 必须先 rebase 到 `origin/dev=0a877d7` 后重新评测，合并门槛见 [`docs/review/01-开放PR状态与合并门槛.md`](../review/01-开放PR状态与合并门槛.md)。

> 每一项安全功能都能**单独开启/关闭**;每个**区域(闸门)**可独立选择"要不要加 judge、加什么后端、用什么模式、阈值多少",全部可自定义,并提供**预设档**一键套用。
> 关联:[09 检测规则强化 §P6](09-检测规则强化.md) · [05 控制台能力规划](05-控制台能力规划.md) · [07 功能实现路线图](07-功能实现路线图.md) · 模型接入设置(三协议/本地私有化/密钥掩码,见 `assistant_rbac_and_model_config`)

## 1. 动机(为什么要"分级 + 按区域可配")

LLM-judge 语义层**补召回有效、但有延迟代价**,而且代价和收益**因区域、因客户而异**——一刀切不行,必须让客户按自己的威胁面 / 算力 / 合规 / 延迟容忍**逐区域权衡**。

实测(冻结语料 v1.0.0,200 条;judge 用 deepseek-flash 全量跑,对照不加):

| 指标 | 不加 judge | 加 judge(全量) | 目标 |
| --- | --- | --- | --- |
| 召回 BSR | 78.8% | **94.1%** | ≥80% |
| ASR | 21.2% | **5.9%** | — |
| 误报率 FPR | 0.0% | **0.0%**(保持) | ≤10% |
| Utility | 100% | 100% | ≥85% |
| **P95 延迟(网关侧)** | **0.7ms** | **3234.7ms** | ≤500ms |

弱桶 ASR(漏过率,越低越好):jailbreak 54.2%→**16.7%**、直接注入 38.5%→**7.7%**、间接注入 35.7%→**0%**、数据投毒 50%→**0%**;输入闸门召回 61.8%→**88.8%(+27pp)**。

**结论**:judge 把最弱的注入/越狱桶 ASR 砍 3–5 倍、0 误报不破,**唯一代价是延迟**;全量跑 P95 破 500ms 线。所以不是"要不要 judge",而是"**在哪个区域、用什么模式上 judge**"——这正是本功能要交给客户的旋钮。

## 2. 区域(闸门)枚举

管线现有四道闸,各自威胁面不同,应可独立配置(对应 `core/pipeline.py`):

| 区域 | 入口 | 威胁面 | 延迟敏感度 |
| --- | --- | --- | --- |
| 输入闸门 | `screen_input` | 访客输入的提示注入/越狱 | 高(用户在等回复) |
| 工具返回闸门 | `screen_tool_return` | 工具结果里的间接注入(投毒文档/来信) | 中 |
| 出口检测 | `screen_output` | 企业智能体回复里的数据外泄/危险内容 | 中(可异步) |
| 工具治理 | `evaluate_intent` | 越权/外泄链/SSRF 等动作 | 高 |

## 3. 每个区域可配置项(全部可自定义)

1. **启用哪些检测器**(多选):`keyword_rules` / `secret_egress` / `manifest_guard` / `disclosure_egress` / `llm_judge` / …(新增检测器自动出现在清单——复用注册表单一真源)。
2. **judge 后端**:模型 + 端点 + 协议,直接**复用"模型接入设置"**(OpenAI 兼容 / 本地私有化 air-gapped / 密钥掩码)。可与主对话模型不同(如主模型走云、judge 走本地保数据不出域)。
3. **运行模式**(见 §4):off / 全量 / 灰区级联 / 异步旁路。
4. **阈值**:灰区 band 上下界(`gray_low`/`gray_high`)、judge 单独贡献封顶(`max_score`,默认 0.7,即 judge 独自最多升"人工复核"、不自动拦)。

## 4. judge 运行模式(每区域独立选,附实测)

judge 单次调用成本(实测,每条):本地 qwen3-8b **~0.8s**、qwen3-14b 0.82s、云 deepseek 1.53s、deepseek-flash 2.21s、mimo 2.07s。基线确定性检测 P95 **0.7ms**。

**实测对照(冻结语料 v1.0.0,judge=本地 qwen3-8b,air-gapped):**

| 模式 | 召回 | FPR | P95 延迟 | judge 调用占比 |
| --- | --- | --- | --- | --- |
| off(纯规则基线) | 78.8% | 0% | 0.7ms | 0% |
| 级联 `gray_low=0.2` | 79.4% | 0% | 0.8ms | ~1% |
| 级联 `gray_low=0.0`(=判所有未拦下) | **94.1%** | 0% | **573.9ms** | ~50% |
| 全量(每条都判) | 94.1% | 0% | 575.3ms | 100% |
| 异步旁路(仅特定区域可用,见 §4.1) | ~94%(滞后一拍) | 0% | **~0.7ms** | 50%(并行,不在关键路径) |

**关键认知(实测纠偏,避免踩坑)**:

1. **本检测器 keyword 分是"二极的"**——要么 ≥0.6(强命中)、要么**恰为 0**(无信号),几乎无中间灰区。规则漏网的 35 条攻击 keyword 分**全为 0**,与良性同档,**没有任何分数阈值能把二者分开**。
2. 所以"灰区 band 只判中间分"在当前检测器上**几乎没有召回增益**(`gray_low=0.2` → 召回仅 79.4%,等于白接);`gray_low>0` 仅当未来检测器产出**分级分数**时才有价值。
3. 要补召回**必须判 0 分档**(`gray_low=0.0`),但那等于判 ~50% 输入(良性多的生产流量里更高)→ **P95 ≈ judge 单条延迟**,压不到 0。
4. 级联 `gray_low=0.0` 相对全量的真实价值:**同召回、同 P95,但 judge 调用量减半**(规则已拦的≥gray_high 不重判)→ **省一半算力 / 提吞吐 / 降中位延迟**,但**尾延迟(P95)不变**(两者都判 >5% 流量)。
5. 要 P95 既 ≤500ms(乃至 ~0.7ms)又保召回,只有两条路:**① 更快的 judge 模型**(更小模型/蒸馏分类器,把单条压到 ~100–200ms)、**② 异步旁路**(仅特定区域可用,见 §4.1)。**不是调 gray_low**。

### 4.1 异步旁路:只在"枢衡控制延迟下游动作"的区域才成立(实测路径分析)

异步=输入照常放行、judge 并行跑、裁决落下游闸门。**但它对前置网关(headline)不成立**:

- **前置网关路径**(`/gateway/chat`):流程是 `screen_input`(同步)→ **仅放行才转发**企业智能体 → `screen_output`(同步)。输入闸门的**核心保证就是"恶意输入根本不进企业智能体"**。异步会**先转发再判**——恰好让 judge 要抓的那 35 条零信号注入进了企业智能体(确定性规则已经拦的不需要 judge);若企业智能体内部已执行副作用动作(发邮件/改库),裁决再到也救不回。**异步直接削弱了输入闸门存在的意义**。出口闸门同理——回复发出去就收不回,必须同步。
- **所以前置网关:输入/出口闸门必须同步**。延迟杠杆是**更快的 judge 模型**或**接受 ~575ms**(本地 8B;相对企业智能体本身数秒的处理,占比 <15%,实务可接受)。
- **异步只适合"枢衡自己控制、且动作延后发生"的区域**:典型是 **AI 操作助手**路径(`screen_input` → 模型规划(数秒)→ `evaluate_intent` 工具治理)。judge(~0.8s)在模型规划期间并行跑完,工具治理时裁决已就绪 → 操作员等待 +0ms、又不漏。这是异步的**唯一干净落点**,且属加分项非 headline。

**结论**:别为前置网关做异步(削弱安全保证换已可接受的延迟);网关走同步级联 + (可选)更快模型;异步留给助手工具治理。

## 5. 预设档(tiers,一键套用,免逐项配)

多数客户不会逐区域调旋钮,给开箱预设(可在其上微调):

> 前置网关的输入/出口闸门**必须同步**(异步会削弱"恶意输入不进企业智能体"的保证,见 §4.1);异步只用于助手工具治理。

| 预设 | 输入闸门(网关) | 出口检测(网关) | 助手工具治理 | 面向 |
| --- | --- | --- | --- | --- |
| **轻量** | 规则 | 规则 | 规则 | 算力紧 / 仅要确定性 0 误报基线 |
| **标准**(默认) | 级联 `gray_low=0`(同步) | 全量(同步) | judge 异步 | 在线主用,网关同步保召回(~575ms,占企业智能体数秒的小头)、助手侧 judge 并行不加等待 |
| **严格** | 全量(同步) | 全量(同步) | judge 异步 | 高敏,网关每条都判 |
| **合规·air-gapped** | 级联 `gray_low=0`(**本地模型**) | 全量(本地) | judge 异步(本地) | 政务私有化,数据不出域 |

> 注:预设里不用"judge 灰区"(实测对二极分数无增益,见 §4)。网关要更低延迟只能换**更快的 judge 模型**(把单条压到 ~100–200ms),不是改阈值、也不是异步。

## 6. 配置 schema 演进(后端)

- **现状**:`fulcrum.yml` 的 `detectors` 是**扁平清单**,`build_pipeline` 一次性装配,`pipeline.detect_inputs` 对**所有闸门跑同一组检测器**(`_run_detectors` 遍历 `self._detectors`)。无法按区域区分。
- **目标**:`detectors` 升级为**按区域分组**(向后兼容:扁平清单=四区域同配)。`detect_inputs(ctx, spans, *, zone)` 增 `zone` 形参,按区域取该区域的检测器集与模式;`screen_input/screen_output/screen_tool_return/evaluate_intent` 各自传自己的 `zone`。
- **级联已落地**为对等能力组合 `detector/injection_cascade`(keyword + judge,阈值门控,fail-safe),无需改 `core`,放进某区域 detectors 即可。**异步**待建:把 judge 移出关键路径、裁决回写 `ctx`/审计供下游闸门消费(P_c)。
- 配置热加载、落盘位置、与策略中心的关系沿用现有 `GatewayConfigStore` 模式。

## 7. 控制台 UI(设置页)

- **按区域卡片**:四张卡(输入/工具返回/出口/工具治理),每卡:检测器多选开关 + judge 下拉(模型 / 模式 / 阈值)。
- **预设档快捷**:顶部一行预设(轻量/标准/严格/合规),选中即套用、可继续微调。
- **judge 后端选择**复用模型接入设置(三协议 / 本地私有化 / 密钥掩码);**密钥只存后端**,前端只显掩码。
- **权限**:仅超管 / 管理员可改(复用 `PERMISSIONS` 单一真源,低权用户只读或不可见)。
- **文案纪律**:只留功能必需的简短提示,不写解释性/营销性废话,不暴露文件路径 / env 变量名(见 `no-filler-ui-text`)。

## 8. 安全默认 / fail-safe

- 默认预设 = **标准**;任何区域 judge 端点不可达 / 配置错误 → 该区域 judge **降级 no-op**,确定性规则照常,**绝不 fail-open、也绝不因 judge 故障反而拦一切**(judge 仅作增益,见 `detector/llm_judge` 已实现的降级)。
- 改配置走 RBAC + 审计留痕;误配只降安全等级、不破基线 0 误报。

## 9. 落地阶段

- [x] **P_b 级联机制 + 实测标定**:`detector/injection_cascade`(keyword + judge,阈值门控,fail-safe)+ 8 单测;`fulcrum.eval --judge {full,cascade}`。**实测结论(见 §4)**:二极分数下灰区门控无召回增益;`gray_low=0` 同召回同 P95、judge 调用减半;P95 压不到 0 → 需异步/更快模型。默认 `gray_low=0.0`。
- [ ] **P_a 配置 schema 按区域化**:`detectors` 支持分组 + `detect_inputs(zone=…)`;扁平清单向后兼容(四区域同配)。**下一步主线**(让"每区域可配"真正可用)。
- [ ] **P_d 控制台设置页**:按区域卡片 + 预设档 + judge 后端选择(复用模型接入设置)+ RBAC。
- [ ] **P_e 预设档**:轻量/标准/严格/合规 四档落地 + 文档。
- [ ] **更快 judge 后端(网关降延迟的唯一干净杠杆)**:小模型/蒸馏分类器把单条压到 ~100–200ms,使同步级联/全量也进 500ms 线——网关不能用异步(§4.1),这是降延迟的正路。
- [ ] **(加分,非 headline)P_c 异步旁路**:**仅助手工具治理**适用(judge 与模型规划并行,工具治理时裁决就绪)。**前置网关不做**(异步削弱"恶意输入不进企业智能体"的保证,§4.1)。
- 每阶段守门:FPR 不升、延迟回归可测、单测 + ruff 全绿(沿用 [09 §4 验收](09-检测规则强化.md))。
