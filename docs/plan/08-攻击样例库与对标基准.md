# 08 · 攻击样例库标准化与竞品对标基准

> 本文件是「枢衡攻击样例库(Fulcrum Attack Corpus)」这条线的**单一真源**。
> 定位:这是产品的**核心可售资产**——对标杀软病毒库,商业模式为**年订阅 + 持续更新库**(见 [06-商业模式]),
> 因此必须**标准化、可冻结、可复现、每次跑出标准报告**。
> 状态标记:✅ 已完成 · �doing 进行中 · ⬜ 待办。最后更新 2026-06-18。

---

## 1. 背景与定位

- **是什么**:一套高难度、分类化、带标准分类 ID 的 LLM/智能体安全**对抗样本库 + 评测基准**,用于量化网关真实防护覆盖,并作为长期售卖的"病毒库"。
- **为什么要"硬"**:旧冒烟集(`govoffice.jsonl` 28 条)是"玩具"——模型自己就会拒、关键词一抓一个准,跑出来全绿,**掩盖真实差距**。新库刻意收录"模型不拒、必须靠网关"的样本(语义注入、混淆/隐写、跨步污点、SSRF、LOLBins、投毒、供应链),**漏判率=路线图,不是 bug**。
- **两类资产要分清**(杀软同理):
  - **样本库(zoo)** = 分类 payload/测试样例 → 驱动**评测**(本文件)。
  - **特征库(signatures)** = `keyword_rules`/`argrisk` 等检测规则 → 驱动**拦截**(代码)。
  - 关系:样本库是"考卷",特征库是"答题能力";拿前者考后者 = 差距报告。
- **商业化**:库分**冻结基线版**(免费/试用)+ **订阅增量更新**(新手法、新 CVE/技术映射、季度刷新)。订阅 = 持续拿到对最新攻击的检出能力验证。

## 4. Schema 规范(`EvalSample`,详见 `corpus/SPEC.md`)

必填:`sample_id`(稳定唯一,命名见下)· `attack_type` · 载荷三选一(`input` / `reply` / `target_tool`+`tool_args`)· `ground_truth_malicious` · `expected_action`∈{allow,sanitize,approve,block}。
路由:`target_tool`→工具级(`evaluate_intent`);否则 `reply`→出口级(`screen_output`);否则→输入级(`screen_input`)。
标准化元数据(可选):`technique`(手法 slug)· `owasp` · `mitre_atlas` · `mitre_attack` · `cwe` · `severity` · `source`(self / upstream:<repo>)· `version_added`(SemVer)· `references` · `tags`。
**真值标注协议**:按"**安全应然标准**"标(网关**正确情况下该怎么判**),非按当前实现能否检出 → 故漏判率反映真实差距。
**ID 命名规范**:`<前缀>-<序号>`,前缀=攻击面(tg-file/tg-path/tg-ssrf/tg-cmd/tg-exfil/inj-d/inj-i/enc/jb/poi/sc/eg/neg)。

## 5. 版本与冻结策略(订阅模式的技术底座)

- **SemVer**:`MAJOR.MINOR.PATCH`。MAJOR=分类法/Schema 破坏性变更;MINOR=新增样本/攻击面;PATCH=修订标注/修字。
- **冻结基线**:`v1.0.0`(2026-06-18,200 条)= 不可变快照,打 git tag,`VERSION` 记录,`CHANGELOG.md` 记每次增量。
- **更新节奏(订阅交付物)**:季度增量 + 重大新手法即时补;每次增量附"新增手法清单 + 对当前网关的检出 delta"。
- **冻结意味着**:基线版样本 ID 与标注不再改;新内容只追加,不动旧条目(保证横向可比、复现稳定)。

## 6. 报告规范(每次跑必产出)

`python -m fulcrum.eval --dataset samples/eval/corpus [--policy ...]` 每次产出:
- **标准 md 记分卡**:运行元信息(库版本/策略/日期)+ 主指标表 + 按 OWASP/ATLAS/严重度的**覆盖矩阵** + 分桶表 + FP/FN 清单。
- **完整 json**:逐样例明细(复现/错误分析)。
- 主指标(对齐 [00-评测指标体系]):召回/BSR · FPR · 精确率 · ASR 及降幅 · Utility · 处置准确率 · 审计完整率 · Hash-chain 通过率。

## 7. 当前基线结果(v1.0.0,2026-06-18)

200 条 · 两套策略对比:

| 指标 | default 策略 | gov_demo 策略 | 目标 |
|---|---|---|---|
| 召回/BSR | 50.6% | 47.1% | ≥80% |
| FPR | 6.7% | 6.7% | ≤10% |
| Utility | 93.3% | 93.3% | ≥85% |
| 处置准确率 | 49.0% | 46.0% | ≥85% |
| 审计/Hash-chain | 100% | 100% | =100% |

**三条主结论**:① 工具层强(`unauthorized_tool` 召回 93%);② 输入层弱(注入/越狱/投毒召回仅 ~21%,语法检测漏语义/混淆);③ 两策略工具层缺口互补(default 缺 funds/case/file.delete,gov_demo 缺 12 条 SSRF)。详见 `docs/eval/corpus-gap-report.md`。

## 8. 加固待办(差距→路线图)

- **P0 输入侧语义/混淆检测(~70 漏判)**:匹配前归一化(NFKC+剥零宽+同形字折叠+de-leet+去双向+全角)、递归解码限深、语义注入判别(小模型/LLM)。
- **P1 工具层策略补洞(改 YAML)**:统一 http.request 网络规则+SSRF 内网判定、补 file.delete 破坏性动作、IP 混淆归一、路径双重解码、命令正则补 certutil -decode/reg save/${IFS}。
- **P1 供应链上管线**:把 `manifest_scanner` 接入请求路径(现离线,样本只过 keyword_rules)。
- **P2 出口增强**:系统提示/连接串/策略泄露检测、Markdown 图片/链接渲染外泄拦截。
- **P2 跨步污点**:需多步回放 harness(现 `chain_analyzer:noop`、单 intent/样本)。

## 9. 竞品对标基准(用我们的库给同行打分)

> 目标:像 AV-TEST/AV-Comparatives 那样,用我们的标准库去跑同类系统,拿到**竞品检出率**做横向对比,凸显枢衡覆盖与"一体化"优势。

- **同类系统(候选)**:
  - 输入防护类(可拉取本地跑):**Meta Llama Prompt Guard 2**(HF 分类器)· **ProtectAI LLM Guard** · **deepset/protectai deberta 提示注入分类器** · **Rebuff** · **NVIDIA NeMo Guardrails** · **Vigil**。
  - API/闭源类(只能取公开基准或受限试用):**Lakera Guard** · **Azure AI Content Safety / Prompt Shields** · **AWS Bedrock Guardrails** · **OpenAI Moderation**。
- **可比范围**:多数竞品只做**输入侧**(注入/越狱检测),故公平对比在 `01-input-injection`+`02-jailbreak`+`04-poisoning` 子集(约 80 条恶意+硬负例);工具层/出口/供应链是枢衡差异化优势,单列说明竞品不覆盖。
- **做法**:① 建 `samples/eval/benchmarks/` 适配器(把我们的输入子集喂给竞品检测器,取 block/allow,按我们的真值算检出率/FPR);② 能本地拉的(HF 小模型)实跑;③ 闭源 API 取官方/论文公开数字并注明来源与口径差异;④ 产出**对比记分卡**(各系统在我们库上的检出率/FPR/覆盖范围)。
- **状态**:⬜ 待标准化冻结后启动(本文件 §10 执行清单)。
