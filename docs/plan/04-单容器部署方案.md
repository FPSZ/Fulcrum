# 枢衡 Fulcrum · 单容器部署方案

> 本文回答:**枢衡能不能"一个 Docker 镜像、一条命令、跨平台(Linux/Windows/macOS)起服务"**,以及它如何落地。
> 状态:**✅ 已落地**(2026-06-16)。产物:[deploy/Dockerfile](../../deploy/Dockerfile)、[deploy/docker-compose.yml](../../deploy/docker-compose.yml)、[.dockerignore](../../.dockerignore)、[deploy/README.md](../../deploy/README.md);用法见 deploy/README。落地进度以 [03-进度看板](03-进度看板.md) 为准。
> 关联约束:私有化、单租户、数据不出域;密钥只走 `.env`、不进镜像、不入前端。
>
> **一条命令**(仓库根目录):`cp .env.example .env && docker compose -f deploy/docker-compose.yml up -d --build` → <http://localhost:8000> 即控制台,API 同端口。**只起生产服务**(前端 + 网关/管控 API,单进程);企业智能体靶机(:8800)、政务沙盘 demo 等**测试服务不在镜像/编排内**。

---

## 1. 目标

一句话:**`docker build` 出一个镜像,`docker run` 一个容器,就同时提供"控制台前端 + 安全网关 API",并且同一镜像在 Linux / Windows / macOS 上行为一致。**

这与项目定位天然契合:政企私有化、单机单租户部署,运维越简单越好,不引入额外中间件。

---

## 2. 为什么本项目适合"单容器"

| 形态特征 | 现状 | 对单容器的意义 |
| --- | --- | --- |
| 后端 | 单体 FastAPI + uvicorn,纯 Python 进程(`python -m fulcrum`) | 一个进程即全部服务端逻辑 |
| 存储 | SQLite(文件),无外部 DB | 无需 PostgreSQL/Redis 等附加容器 |
| 依赖中间件 | 无消息队列、无独立缓存、无独立网关 | 不需要 Compose 编排多服务 |
| 前端 | Vite 静态产物(`console/dist`) | 可由后端直接托管,无需单独 nginx 容器 |
| 部署模型 | 私有化、单机、单租户 | 单镜像单容器就是合理的最终形态,而非临时简化 |

跨平台说明:Windows / macOS 通过 Docker Desktop 内置的 Linux 虚拟机运行**同一个 Linux 镜像**,因此"一次构建、三端一致"。无需为不同 OS 出不同制品。

---

## 3. 前置改造(已完成)

要做到"一个容器同时出 API 和控制台",后端需托管前端静态资源——**已落地**:

- **后端托管前端静态资源**:FastAPI 适配层 [`adapters/api/app.py`](../../src/fulcrum/adapters/api/app.py) 的 `_mount_frontend()` 把 `console/dist` 挂为静态站点(`StaticFiles` + `FileResponse`),并对前端路由做 SPA fallback(未命中 API/静态文件的路径回退 `index.html`)。由 `FULCRUM_FRONTEND_DIR` 控制(留空则只出 API)。
  - 仅影响 **adapters 层**,不触碰 `core`(核心层不依赖框架的铁律不变,见 [架构总览](../arch/00-技术架构总览.md)、[后端骨架规范](../arch/01-后端骨架与扩展规范.md))。
  - 单端口同时出 `/`(控制台 SPA)、`/gateway/*`(网关)与管控/审计/鉴权 API。
  - 已本地验证:`FULCRUM_FRONTEND_DIR=console/dist python -m fulcrum` 后 `GET /`(控制台)、深层路由 `GET /events`、`GET /healthz` 均 200。

## 4. 镜像设计(多阶段构建)

```text
deploy/Dockerfile（规划）
─────────────────────────────────────────────
Stage 1  前端构建   node:20-slim
  - 复制 console/ , npm ci , npm run build  →  /console/dist

Stage 2  运行时     python:3.11-slim
  - 安装 uv,按 pyproject.toml 锁定依赖装 fulcrum
  - 复制 src/ 与 data/policies 等只读资产
  - 从 Stage 1 复制 dist  →  后端静态目录
  - EXPOSE 8000
  - CMD ["python", "-m", "fulcrum"]
```

要点:

- **Python 固定 3.11**(`requires-python >=3.11,<3.12`,见 [pyproject.toml](../../pyproject.toml));镜像基础镜像与之对齐,避免本机 3.14 漂移。
- 依赖安装走 `uv`,复用锁定版本,保证可复现。
- 多阶段:Node 只在构建期出现,**不进最终运行镜像**,镜像保持精简。
- 配套 `.dockerignore`:排除 `node_modules/`、`.venv/`、`__pycache__/`、`data/runtime/`、`console/dist`(由构建阶段重新生成)等。

## 5. 运行与数据(跨平台一致)

```text
docker build -t fulcrum:dev -f deploy/Dockerfile .

docker run -d --name fulcrum \
  -p 8000:8000 \
  --env-file ./.env \
  -v fulcrum-data:/app/data/runtime \
  fulcrum:dev
```

约定:

- **密钥/配置只走 `--env-file ./.env`**(模型 endpoint、API key、DB 路径、策略路径),**绝不写进镜像、绝不入前端、绝不入库**。镜像里仅保留 `.env.example` 占位。
- **数据持久化挂卷**:`data/runtime/`(SQLite 审计库等运行产物)挂 Docker named volume 或宿主目录,容器重建数据不丢。该目录已被 `.gitignore` 排除,不入库。
- 端口:容器内 `8000`,宿主可按需映射。
- 三端命令一致(上面的命令在 Linux/Win/macOS Docker Desktop 通用)。

---

## 6. 范围边界(本阶段不做)

- 不出 `docker-compose.yml` / Kubernetes 清单:单容器即满足 MVP 与私有化交付,Compose 仅当未来确需多服务(如外置 DB)时再补。
- 不做多架构(amd64/arm64)发布流水线:先保证本地 `docker build` 可用,镜像发布与签名后置。
- 不做 TLS 终止 / 反向代理:私有化内网部署优先;如需对外暴露,由部署方在前置网关处理,不绑进本镜像。
- 不做自动伸缩 / 多副本:与单租户单机定位一致。
