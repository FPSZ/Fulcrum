6. #114 核对部署端点、审计类型和“未落地能力”的表述，避免把计划写成既有事实。

## 6. Fork 与 PR 流程

- 本地 `origin` 是上游 `FPSZ/Fulcrum`；`waynejoon/Fulcrum` fork 已存在，但当前仅有 `main`，尚无 `dev`。
- 开始实际开发时，将 fork 的 `dev` 对齐最新上游 `origin/dev`；开发、测试和提交均在 fork 的 `dev` 完成。
- 创建 PR 时固定为 `waynejoon:dev` -> `FPSZ:dev`。不向上游 `dev` 或 `main` 直接推送，不执行合并。
- 每项已确认开发任务使用两名子 agent：编码子 agent 实现最小变更；本地测试与代码审核子 agent 独立复查 diff、运行验收并报告问题；编排负责人决定范围、处理问题并创建 PR。
