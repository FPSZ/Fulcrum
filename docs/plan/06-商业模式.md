# 枢衡 Fulcrum · 商业模式(盈利模式)

> 本文回答:**枢衡靠什么持续盈利**,以及为什么这套打法契合"政企 / 私有化 / 智能体安全"的产品形态。
> 用途:挑战杯答辩与商业计划书的"盈利模式"章节素材。
> 上游依据:产品定位 [plan/00 项目大方向](00-项目大方向.md);部署形态 [plan/04 单容器部署方案](04-单容器部署方案.md);企业版特性 [plan/05 控制台能力规划](05-控制台能力规划.md)。
> 安全红线不变:私有化、单租户、数据不出域。

---

## 1. 形态决定模式

枢衡是**政企私有化、单租户、自托管**的智能体安全中台(数据不出域)。这一形态直接排除了两类常见互联网打法,并指向"安全软件 + 政企交付"的经典组合:

- ❌ **不做**:纯 SaaS 多租户、按我们云端 API 调用量计费(与数据主权冲突)。
- ✅ **适合**:许可授权 + 订阅 + 服务三层叠加(下文 §3)。

---

## 2. 自托管 / Docker 部署项目的通行盈利模式(参照)

| 模式 | 怎么收钱 | 代表项目 |
| --- | --- | --- |
| 开放核(Open-Core) | 社区版免费自托管引流,企业版收费(SSO/RBAC/审计/高可用/高级能力) | GitLab、Sentry、Grafana、MinIO |
| 双授权 / 源可见许可 | 免费版用 AGPL/BSL/SSPL,商业授权避开 copyleft 或闭源使用 | MongoDB、Elastic、Redis、CockroachDB |
| 年度订阅 + 许可证 | 自托管,按部署/节点/受保护对象收年费,含升级与支持 | 多数企业安全软件 |
| 支持与 SLA | 软件免费,收维护合同(响应时效、专属支持) | Red Hat |
| 订阅式内容更新 | 软件是壳,规则/威胁情报/检测模型持续更新按年订阅 | 杀毒、奇安信/深信服情报订阅 |
| 实施与集成服务 | 项目制:部署、对接、定制检测、策略调优、合规陪跑 | 国内政企安全集成商主力收入 |
| 软硬一体机 | 把软件做成安全盒子卖硬件 | 国内安全厂商常见 |

## 3. 枢衡的盈利模式:许可 + 订阅 + 服务(三层叠加)

### 3.1 主力一:License 授权 + 年度订阅

- **授权计费维度**:按 部署实例 / 受保护 Agent 数 / 网关吞吐 分档。
- **订阅内容(复购核心)**:策略库、检测规则、供应链威胁情报、攻击样本集的**持续更新** + 版本升级 + 技术支持 SLA。
- **为什么健康**:安全产品的"规则 / 情报订阅"天然每年续费,形成**经常性收入(ARR)**,而非一次性买断。

### 3.2 主力二:开放核 → 企业版(与已规划特性咬合)

- **社区版(免费,引流)**:核心网关 + 基础检测,**一个 Docker 即跑**(见 [04 部署方案](04-单容器部署方案.md))。用于开源声量、政企 POC、降低进场门槛。
- **企业版(收费)**:直接复用 [05 控制台能力规划](05-控制台能力规划.md) 的内容——**权限组 RBAC、AI 操作助手、完整审计溯源 / hash-chain 取证、高可用、高级检测器、评测报告**。
- **好处**:免费版讲技术先进性,企业版收"合规 + 管控 + 审计"的钱;**不需要重写架构**,付费特性就是 M4 已规划项。
- **免费 / 付费具体怎么切**(尤其规则-情报库这条最敏感):见 §4。

### 3.3 主力三:实施与集成服务(政企项目占比大)

私有化部署、与现有 Agent / 办公系统对接、**定制策略与检测器**、等保 / 密评合规陪跑。毛利高,且是中标项目的常规科目。

### 3.4 可选:软硬一体机 / 合规增值包

- 安全一体机契合国内政企熟悉的采购形态。
- 叠加"等保 / 密评适配包"作为增值,贴合政企采购预算口径。

## 4. 免费 / 付费分界线(开放核的核心难题)

### 4.1 难题

开放核最尖锐的矛盾:**免费版若不更新规则 / 情报库,用户被打穿,会反噬品牌("产品垃圾");若更新,那不就是收费内容?**

### 4.2 原则:收费线画在"时效 / 策展 / 运营 / 合规 / 责任",不画在"有没有基本防护"

一个会让用户被打穿的免费版,比没有免费版更糟——它主动毁品牌。所以:

- **免费版必须是"真的能用、真的更新"的**:开源检测引擎 + **开源社区规则库**(我们持续公开更新、社区可贡献),覆盖**已知 / 常见**攻击。免费用户被打穿,只会是被**新型 / 定向**攻击——与任何免费安全工具同理,不是"扣了基础防护"。
- **付费价值挪到免费用户用不到、企业必须有的维度**(见 §4.4),免费不残废、付费仍硬刚。

这是成熟安全开源项目的通行做法,无人因此被骂垃圾:

| 项目 | 免费 | 付费 |
| --- | --- | --- |
| Suricata / Snort | ET Open 规则(免费、持续更新) | ET Pro:更快、更全、厂商策展 |
| ClamAV | 免费引擎 + 免费社区签名 | 商业 AV:实时情报 + 响应 SLA |
| Wazuh / Trivy / Semgrep | 免费规则真能跑 | 高级规则 + 管理 + 支持 |

### 4.3 关键:同样的情报,付费买"更早拿到"

规则 / 情报**最终都会进社区集**;企业付费买的是**时效**——付费档新情报**几小时内**下发,社区档按**公开发布节奏**(如周更)。"零日当天就受保护" vs "一个月后",这是政企最愿意付费的点,且不以"饿死免费用户"为代价。

### 4.4 免费 vs 付费维度对照

| 维度 | 社区版(免费) | 企业版(付费) |
| --- | --- | --- |
| 检测引擎 | ✅ 开源 | ✅ 同引擎 |
| 基础规则库 | ✅ 社区集,公开更新 | ✅ 含社区集 |
| 情报时效 | 公开发布节奏(如周更) | **SLA,小时级下发** |
| 专属 / 政企情报 | — | **中文语境 / 政企 / 新型 Agent 攻击 / 供应链源** |
| 高级检测 | 规则匹配 | **LLM-judge / 行为分析 / 深度归因** |
| 管控合规 | 单机基础 | **RBAC / 集中管控 / 审计·等保密评报告 / HA / SSO / AI 助手** |
| 支持与责任 | 社区支持 | **契约 SLA + 厂商背书 / 责任主体** |

### 4.5 被打穿的叙事也随之改变

不是"产品垃圾",而是"**你在没有 SLA 的社区档,企业档当天就拦住了**"——这恰恰是促转化的故事(连商业 AV 也会偶尔被绕过,卖的就是时效与责任)。

## 5. 收入结构与客户旅程

```text
开源社区版(Docker 一键跑) → POC 验证 → 企业版授权 + 年度订阅 → 实施集成服务 →（可选）一体机 / 合规包
        引流 / 声量              进场            经常性收入(ARR)         项目制高毛利        增值
```

- **一次性**:企业版首年授权、实施集成、一体机。
- **经常性(ARR)**:订阅续费(规则 / 情报 / 升级 / SLA)、企业版年费——估值与可持续性的核心。

---

## 6. 一句话定位

> **开放核引流 + 企业版授权(按部署 / 受保护 Agent 计费)+ 规则 / 情报年度订阅 + 政企实施服务**,四条叠加。
> 比赛叙事:**社区版一个 Docker 即跑(技术先进性),企业版做深合规与管控(可持续盈利)**。

---

## 7. 边界与待定

- 具体定价档位、开源许可证选型(AGPL / BSL / 自定义)留待商业化阶段确定,本文只定方向。
- 不承诺未经验证的市场规模与财务数字;BP 中的量化测算另行调研支撑(避免把假设写成结论)。
