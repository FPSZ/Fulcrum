# 10 · 页面验收标准（企业级）

> 目的：钉死一条底线 —— **每个页面都必须真实可用、端到端有数据**，而不是「前端 mock + 一点后端、根本看不到在哪用」。
> 验收方式：按本文逐页核对，能勾完即视为达标。判定口径只有两档：**真实**（数据来自运行中的后端/管线）/ **占位**（前端写死或合成，未接后端）。

本轮（2026-06-21）已把「首页 + 实时事件」从占位拉到真实，并补齐**网关实测**页 —— 这是此前最大的缺口：
全系统此前**没有任何页面能真正"用"网关**（只能在设置页配置上游、或走独立沙盘 demo）。

## 0. 一键起栈（验收前置）

三个进程都要起，缺一不可：

| 进程                       | 命令                                                     | 端口  | 作用                                       |
| -------------------------- | -------------------------------------------------------- | ----- | ------------------------------------------ |
| 控制台后端                 | `FULCRUM_LIVE_FEED_ENABLED=1 FULCRUM_LIVE_FEED_GATEWAY=1 uv run python -m fulcrum` | :8000 | API + 实时流量驱动(政企智能体在环)        |
| 模拟政企智能体（被保护方） | `uv run python -m fulcrum.enterprise`                  | :8800 | 网关放行后转发的真实目标                   |
| 控制台前端                 | `cd console && npm run dev`                            | :5173 | 浏览器访问**http://localhost:5173/** |

- `FULCRUM_LIVE_FEED_ENABLED=1`：把 `samples/eval/corpus` 的 200 条攻击/正常语料持续喂进**运行中的管线**，
  产出真实 hash-chain 审计事件 → 首页 KPI、实时事件、工具网关、审计页全部有真实活动在滚动。
  关掉则各页在空闲实例上回退演示 seed（生产默认关）。
- `FULCRUM_LIVE_FEED_GATEWAY=1`：再让 input 级样例走**真网关流**（`screen_input` → 放行才转发 **MiMo 政企智能体(:8800)** → `screen_output`），
  即"用 MiMo 当政企智能体跑测试集"——攻击在输入闸门拦下/挂起(不调模型)、正常请求转 MiMo 取真实回复并过出口闸门；
  事件/总览页的**出口闸门**出现处置即证明 MiMo 在环端到端。不开则纯检测回放(不调模型、零 token)。
- 上游默认指向 `http://127.0.0.1:8800`（native `/chat`），无需额外配置即可端到端。
- 测试集**聚合结果**(检测口径)在 **评测验证** 页:`uv run python -m fulcrum.eval --dataset samples/eval/corpus` 刷新 `docs/eval/results/latest.json` 后,页面显 P0 主表 + 逐样例。

## 1. 头号验收：网关端到端（这条过了，"在哪用"就立住了）

> **网关实测 / 评测验证 是开发者专属页**(真·政企管理员日常用不到),默认隐藏。验收前先到
> **系统设置 → 开发者 → 开启「开发者模式」**,侧栏才出现这两页。生产交付给管理员时关掉即得干净视图。

**页面：监测 → 网关实测**。在输入框点「一键样例」，逐条核对判定链（输入闸门 → 转发决策 → 企业回复 → 出口闸门）：

| 样例                 | 输入闸门应为                           | 是否转发企业智能体 | 期望现象                                            |
| -------------------- | -------------------------------------- | ------------------ | --------------------------------------------------- |
| 正常办事（低保材料） | **放行**                         | ✅ 转发            | 企业智能体（真 MiMo）返回真实材料清单；出口闸门放行 |
| 提示词注入           | **转人工审核**（命中 injection） | ❌ 不转发          | 网关在前置闸门挂起，请求不抵达企业智能体            |
| 数据外泄             | **拦截**（命中 exfiltration 等） | ❌ 不转发          | 网关拦下，企业智能体收不到                          |
| 越权命令             | **拦截/审核**                    | ❌ 不转发          | 同上                                                |

✅ 验收点：

- [ ] 正常请求**真的拿到企业智能体的真实回复**（不是写死文案）
- [ ] 攻击请求**真的没被转发**（forwarded=false）
- [ ] 每次测试后，去 **实时事件** 页能看到对应事件、去 **审计溯源** 页能看到该会话的 hash-chain
- [ ] 这就是「安全不靠智能体自觉，靠前置网关」的可演示证据

> 实测留痕（2026-06-21，真 MiMo 在线）：正常→allow+forwarded+真实回复；注入→approve+injection(0.75)+不转发；外泄→block+exfiltration/obfuscated(0.85)+不转发。

## 3. 单页验收细则（每页一条硬标准）

- **安全总览**：KPI 数字随 §0 流量驱动**实时增长**（刷新或等 15s）。⚠️ 趋势图为示意，不作真实性承诺（见 §4）。
- **网关实测**：见 §1，四类样例分级处置正确 + 正常请求拿到真实回复。
- **实时事件**：列表为真管线事件；点开任一条，证据/归因/处置与 corpus 标注一致；审计链校验标记真实。
- **策略中心**：显示的规则 = `data/policies/default.yml` 实际装配内容（改 yml 重启后页面跟着变）。
- **工具网关**：每行是一次真实工具意图治理（高危被拦/挂起、正常放行），非静态表。
- **操作助手**：换不同角色登录，可调动作数量随权限变；下达意图能给出受治理的规划结果。
- **审计溯源**：选一条会话，时间轴各步 `prev_hash → event_hash` 连续；篡改即校验失败可演示。
- **评测验证**：主结果表数字 = 最近一次 `python -m fulcrum.eval` 的真实产物。
- **供应链**：组件评级 = 真实静态扫描结论。
- **用户管理**：新建/改角色后，操作助手与各页权限即时随之变化（同一套 RBAC 闸门）。

## 4. 已知差距（不阻断本轮验收，列入下一步）

1. **首页趋势曲线 + 流动事件流仍是合成动画**（`console/.../use-live.ts`）。
   KPI 已真实；趋势/流动层待替换为「轮询 `/events` 真时序 + 真分桶」。属 Option B。
2. **审计为内存 sink、无持久化**：重启清零，无历史。`/events`·`/overview` 对非内存 sink 直接返回空
   （`isinstance(InMemoryAuditSink)` 硬闸）。待实现 `SqliteAuditSink` + 跨会话聚合查询。属 Option B。
3. **系统设置多数项为占位**：仅「上游接入」真实可配；其余待按需接后端或明确标注为「规划项」。
