## 0. 定位:这是"地基",不是"功能"

M0 阶段**只搭可运行的空骨架(Walking Skeleton)**:端到端能跑通,但每个能力点都是**桩实现(stub)**。
- ✅ M0 产物 = 契约 + 接口 + 注册表 + 管线编排 + 工程基线 + 开发者指南 + 一条"空管线"端到端跑通。
- ❌ M0 **不写**任何真实检测/策略/扫描业务逻辑(那是 M1+ 队友在骨架上长的)。
- **验收**(见 §11)不是"拦住攻击",而是"空管线跑通 + 队友照规范能无歧义加功能"。

## 1. 架构风格:六边形 / 整洁(轻量)

**一句话**:领域内核(domain + ports)在内,框架与基础设施(FastAPI / DB / 模型 client)在外,**依赖只能向内**。

```
            ┌──────────────────────── adapters(外层)────────────────────────┐
            │  api(FastAPI 入站)   model(模型出站)   audit/persistence(出站) │
            │        │                    ▲                    ▲              │
            │        ▼ 依赖向内            │ 实现 port          │ 实现 port     │
            │   ┌──────────────────── core(内核,无框架依赖)──────────────┐   │
            │   │  domain(领域类型)   ports(抽象接口)   pipeline(用例编排) │   │
            │   └────────────────────────────▲─────────────────────────────┘   │
            │                                 │ 实现 port                        │
            │   capabilities(能力实现:detectors/policy/toolguard/...)          │
            └────────────────────────────────────────────────────────────────┘
                         composition root(app.py)在最外层装配一切
```

**铁律(防跑偏的核心)**:
1. `core/` **不许 import** FastAPI、SQLAlchemy、httpx、任何具体实现——只依赖标准库与 pydantic。
2. `capabilities/` 与 `adapters/` 只依赖 `core` 的**接口与类型**,彼此**不互相依赖**。
3. 谁也不许直接 `new` 一个具体实现塞进核心——一律由 **composition root** 注入(依赖倒置)。
4. 依赖方向**只能向内**:`adapters → core`、`capabilities → core`,反向禁止。

> 用 import-linter 在 CI 里把上述依赖方向**机器化强制**(见 §10),不靠自觉。

## 2. 目录结构

```
src/fulcrum/
├── core/                       # 六边形内核(无框架依赖)
│   ├── domain/                 # 领域类型(pydantic):SourceSpan/ModelRequest/ToolIntent/...
│   ├── ports/                  # 抽象接口(Protocol):Detector/PolicyEngine/Executor/...
│   ├── registry.py             # 能力注册表(插件式扩展点)
│   ├── pipeline.py             # 安全管线用例编排(串联 ports)
│   └── errors.py               # 领域错误类型
├── capabilities/               # ports 的具体实现 —— 队友在这里长功能
│   ├── labelers/               # 实现 SourceLabeler
│   ├── detectors/              # 实现 Detector(注入/越狱/投毒...)
│   ├── attribution/            # 实现 Attributor(来源归因)
│   ├── policy/                 # 实现 PolicyEngine(YAML 策略)
│   ├── toolguard/              # 实现 RiskScorer / ChainAnalyzer
│   ├── sandbox/                # 实现 Executor(受控执行)
│   ├── tools/                  # 受控工具:file/http/shell(实现 Tool)
│   └── supplychain/            # 实现 SupplyChainScanner
├── adapters/                   # 六边形外层
│   ├── api/                    # FastAPI 入站:/v1/chat/completions、/tools/call
│   ├── model/                  # 出站:OpenAI 兼容模型 client(实现 ModelClient)
│   └── audit/                  # 出站:SQLite 审计(实现 AuditSink,hash-chain)
├── config/                     # 配置与设置加载(env / yaml)
├── eval/                       # 评测引擎(用 core 类型)
├── observability/              # 日志 / trace 规范
├── demo/                       # 极小 demo agent(后置)
├── app.py                      # composition root:按配置装配实现 → 注入 pipeline
└── __main__.py                 # `python -m fulcrum` 入口
```

> 每个 `capabilities/<x>/` 子包内放一个 `README.md`,说明该能力的接口、注册名、如何新增。

## 3. 核心领域类型(`core/domain/`)

统一"通用语言",用 **pydantic v2** 模型(可校验、可序列化、可直接当 API schema)。沿用 `02-MVP.md` 已定义并补全:

```python
class SourceSpan(BaseModel):          # 一段输入及其来源/信任
    source_id: str
    source_type: SourceType           # user/document/webpage/retrieval/memory/tool_return/plugin_manifest
    trust_level: TrustLevel           # trusted/semi_trusted/untrusted
    content_hash: str
    excerpt: str
    risk_tags: list[str] = []

class ModelRequest(BaseModel):
    request_id: str; session_id: str
    messages: list[Message]
    sources: list[SourceSpan] = []

class ToolIntent(BaseModel):
    intent_id: str; session_id: str
    tool_name: str
    arguments: dict
    derived_from_sources: list[str] = []   # 归因得到的来源 id
    attribution_confidence: float = 0.0     # 0~1,证据化归因置信度(非形式化 taint)
    risk_score: float = 0.0

class PolicyDecision(BaseModel):
    decision: Disposition             # allow/sanitize/approve/block
    reason: str
    matched_policy_id: str | None = None
    risk_level: RiskLevel             # low/medium/high/critical

class AuditEvent(BaseModel):
    event_id: str; session_id: str
    event_type: AuditEventType
    subject_id: str | None = None
    decision: Disposition | None = None
    evidence: dict = {}
    prev_hash: str; event_hash: str   # hash-chain

class Finding(BaseModel):             # 检测结果(归一)
    kind: str                         # injection/jailbreak/poisoning/...
    score: float
    evidence: dict = {}

class ExecResult(BaseModel):
    ok: bool; output: str | None = None
    side_effects: dict = {}; error: str | None = None

class ScanReport(BaseModel):          # 供应链
    component_id: str
    rating: Disposition               # allow/review/block(此处复用处置语义)
    risks: list[Finding] = []
```

> 枚举(`SourceType/TrustLevel/Disposition/RiskLevel/AuditEventType`)集中在 `core/domain/enums.py`,**唯一真源**,任何模块不得各自定义。

## 4. 端口 / 抽象接口(`core/ports/`)

每类能力一个 `Protocol`(结构化类型,松耦合)。**这就是队友实现功能要"对齐的插槽"**。签名先定、实现后填。

```python
class ModelClient(Protocol):                                   # 出站:真实大模型
    async def chat(self, req: ModelRequest) -> ModelResponse: ...

class SourceLabeler(Protocol):                                 # 输入来源标注
    def label(self, req: ModelRequest) -> list[SourceSpan]: ...

class Detector(Protocol):                                      # 输入风险检测(目标1)
    name: str
    def detect(self, spans: list[SourceSpan], ctx: Context) -> list[Finding]: ...

class Attributor(Protocol):                                    # 证据化来源归因(脊柱)
    def attribute(self, intent: ToolIntent, spans: list[SourceSpan], ctx: Context) -> Attribution: ...

class RiskScorer(Protocol):                                    # 工具调用风险评分(目标2)
    def score(self, intent: ToolIntent, ctx: Context) -> float: ...

class ChainAnalyzer(Protocol):                                 # 任务链/轨迹分析(目标2)
    def analyze(self, session_trace: list[ToolIntent], ctx: Context) -> list[Finding]: ...

class PolicyEngine(Protocol):                                  # 策略判定(目标1/2)
    def decide(self, intent: ToolIntent, ctx: Context) -> PolicyDecision: ...

class Tool(Protocol):                                          # 受控工具
    name: str
    def call(self, arguments: dict, ctx: Context) -> ExecResult: ...

class Executor(Protocol):                                      # 沙箱执行器(目标2)
    def execute(self, tool: Tool, intent: ToolIntent, ctx: Context) -> ExecResult: ...

class SupplyChainScanner(Protocol):                            # 供应链扫描(目标3)
    def scan(self, manifest: dict, ctx: Context) -> ScanReport: ...

class AuditSink(Protocol):                                     # 审计落库(目标4)
    def append(self, event: AuditEvent) -> AuditEvent: ...     # 内部维护 hash-chain
    def verify_chain(self, session_id: str) -> bool: ...
```

> 接口**只进 `core/ports`**;具体实现一律进 `capabilities/` 或 `adapters/`。新增能力 = 新增实现,不改 ports、不改 pipeline。

## 5. 扩展机制:接口 + 注册表(插件式)

队友"加功能"的**唯一标准姿势**:实现接口 → 用装饰器注册 → 在配置里启用。**核心管线零改动。**

```python
# core/registry.py
registry = Registry()                         # kind -> { name -> factory }

# capabilities/detectors/keyword_rules.py
@capability("detector", "keyword_rules")      # 注册名
class KeywordRuleDetector:                     # 实现 Detector 协议
    name = "keyword_rules"
    def detect(self, spans, ctx): ...
```

```yaml
# config/fulcrum.yml —— composition root 按此装配,决定启用哪些实现
detectors:   [keyword_rules]        # 想加新检测器?实现+注册+在这里加一行
policy:      yaml_policy
attributor:  evidence_weighted
executor:    subprocess_sandbox
audit:       sqlite_hashchain
```

- **kind(能力类型)固定**:`labeler/detector/attributor/risk_scorer/chain_analyzer/policy/tool/executor/scanner/audit/model`。
- composition root(`app.py`)读 `fulcrum.yml`,从 registry 取出实现,组装进 `SecurityPipeline`。
- 好处:**开放扩展、对修改封闭(OCP)**——加功能不动核心,评审/测试/汇报都能讲清"谁加了什么"。

## 6. 管线编排(`core/pipeline.py`)

`SecurityPipeline` 是应用层用例,只依赖 **ports**,不知道任何具体实现。M0 用桩跑通下面两条流程:

```text
handle_model_request(req):
  spans      = labeler.label(req)                      # 来源标注
  findings   = [d.detect(spans, ctx) for d in detectors]
  ctx.risk   = aggregate(findings)
  audit(input_detected, evidence=findings)
  resp       = await model_client.chat(req)            # 转发真实模型
  intents    = parse_tool_intents(resp)
  for intent in intents:
      attr     = attributor.attribute(intent, spans, ctx)   # 证据化归因
      intent.risk_score = risk_scorer.score(intent, ctx)
      decision = policy.decide(intent, ctx)                 # allow/sanitize/approve/block
      audit(policy_decided, decision=decision)
      if decision == allow:  executor.execute(tool, intent, ctx); audit(tool_executed)
      elif approve:          audit(tool_pending_approval)    # MVP 默认不执行
      elif block:            audit(tool_blocked)
  return resp

handle_tool_call(call):    # /tools/call 直接入口,复用 attributor→scorer→policy→executor→audit
```

**M0 桩实现(Null Object)**,保证管线端到端跑通且行为可预测:
`PassthroughLabeler`(整体标为 untrusted)、`NoopDetector`(无 finding)、`ZeroAttributor`(置信度 0)、`ZeroRiskScorer`、`AllowAllPolicy`(恒 allow)、`EchoExecutor`(回显不真执行)、`NoopScanner`、`InMemoryAuditSink`(内存 hash-chain)、`FakeModelClient`(回固定响应)。

## 7. API 契约(`adapters/api/`)

- **单一真源**:用 `core/domain` 的 pydantic 模型直接做请求/响应 schema,FastAPI 自动产出 **OpenAPI**;前端按 OpenAPI 生成 client(详见后续 `02-API契约.md`)。
- **入站端点(M0)**:
  - `POST /v1/chat/completions` — OpenAI 兼容,经管线。
  - `POST /tools/call` — 工具网关。
  - `GET  /healthz` — 存活探针。
  - `GET  /audit/{session_id}` — 审计链查询(骨架返回桩数据)。
- adapters 层只做**协议转换**(HTTP ↔ 领域类型)+ 调 `SecurityPipeline`,**不写业务逻辑**。

## 8. 横切规范(配置 / 密钥 / 错误 / 日志)

| 关注点 | 规范 |
|---|---|
| 配置 | `pydantic-settings` 从 `.env` + `config/fulcrum.yml` 加载;**类型化 Settings 对象**注入,不到处读 `os.environ`。 |
| 密钥 | 只走 `.env`(不入库),仓库提供 `.env.example` 占位;`core` 不碰密钥。 |
| 错误 | 领域错误集中 `core/errors.py`(`PolicyViolation/SandboxDenied/AuditError`...);adapters 统一异常处理器映射为 HTTP。 |
| 日志 | `structlog` 结构化日志,字段含 `session_id/request_id/trace_id`;**禁止打印敏感原文**,敏感内容存哈希/摘要。 |
| 失败模式 | 遵循架构总览 §7:安全关键路径 **fail-closed**,可用性路径 fail-open 但留痕。 |

## 11. Walking Skeleton 验收标准(M0 完成定义)

M0 视为完成,当且仅当:
1. `uv sync && python -m fulcrum` 能起服务;`/healthz` 通。
2. `POST /v1/chat/completions` 与 `POST /tools/call` 用**全桩实现**端到端返回结果,并写出审计事件(hash-chain 校验通过)。
3. `pytest` 全绿;`ruff`/`pyright`/`import-linter` 全过;CI 绿。
4. 依赖方向被 import-linter 强制(故意写一条反向依赖会让 CI 失败)。
5. 有 `04-开发者指南.md`:照着能在 **15 分钟内**新增一个 `detector` 并被管线调用——**不改 core、不改 pipeline**。

> 达成后,队友即可在 `capabilities/` 下按接口并行长功能(M1 起替换桩为真实实现)。

## 12. 开发者指南预览:如何加一个检测器(示意)

```
1. 在 capabilities/detectors/ 新建 my_detector.py
2. 写一个类,实现 Detector 协议(name + detect())
3. 加 @capability("detector", "my_detector") 装饰器注册
4. 在 config/fulcrum.yml 的 detectors: 列表加 "my_detector"
5. 在 tests/capabilities/detectors/ 加单测
→ 不需要改 core/、不需要改 pipeline、不需要改别人的代码
```

(完整版进 `docs/arch/04-开发者指南.md`。)

## 13. 与安全问题 / 赛题目标映射

| 端口/能力 | 对应 [01 安全问题](../plan/01-安全问题与实现路径.md) | 赛题目标 |
