# 枢衡 Fulcrum · 备份文件格式与导入契约(单文件数据交换)

> 本文回答:**控制台的数据存在哪、长什么样、导入要上传什么、怎么扩展。**
> 状态:**草稿 v1.1 · 已落地**。无后端时控制台的全部数据(指标 + 事件 + …)经由**单一 JSON 备份文件**交换与持久化。
> 上游依据:[前端骨架与扩展规范](02-前端骨架与扩展规范.md)(功能模块插件化) · 产品形态 AD-11(私有化部署、数据不出域)

## 0. 定位:单文件、自包含、可容错

- **单文件**:一个 `.json` 就是全部数据。不依赖数据库——导入、导出、浏览器持久化都是这一个文件。
- **自包含**:版本化信封 + 元信息 + 按「资源类型」分桶的数据,无外部引用。
- **可容错**:缺桶 / 多桶 / 坏桶都能安全导入,不整包失败、不污染已有数据(见 §3)。
- **可扩展**:加新页面只注册一种新资源,**信封结构不变**,导入导出零改动(见 §4)。

> 为什么是文件而不是库:对位后端 M0「先骨架、可演示」与 AD-11「私有化、数据不出域」——一个可手工核对、可脱敏、可随包分发的文件,比早早绑数据库更适合当前阶段。

## 1. 文件结构

一个版本化信封,`resources` 下按 `kind` 分桶,每桶是一个数组。定义见 [`types.ts`](../../console/src/lib/backup/types.ts)。

```jsonc
{
  "kind": "fulcrum.backup",      // 固定标识,校验入口
  "schemaVersion": 1,            // 信封版本(BACKUP_SCHEMA_VERSION)
  "meta": {                      // 元信息,整体可选
    "exportedAt": "2026-06-14T14:05:00+08:00",
    "instance":   "雄安政务智能体 · 隔离演示环境",
    "note":       "脱敏备份,不含任何真实 payload/密钥/敏感数据",
    "appVersion": "0.1.0"
  },
  "resources": {                 // 核心:按资源类型分桶
    "overview": [ { /* 总览聚合指标,单行 */ } ],
    "events":   [ { /* 风险事件 */ }, { /* … */ } ]
  }
}
```

完整真实样例:[`public/demo-backup.json`](../../console/public/demo-backup.json)。

## 2. 已注册资源(桶)

每种资源 = 一条 `ResourceSpec`(`kind` + 中文 `label` + 校验 `schema`),由对应功能模块注册。当前:

| `kind`     | 标签       | 内容                                   | Schema 定义                                                                 |
| ---------- | ---------- | -------------------------------------- | -------------------------------------------------------------------------- |
| `events`   | 风险事件   | 逐条安全事件(证据/意图/处置/审计…)     | [`features/events/backup.ts`](../../console/src/features/events/backup.ts) |
| `overview` | 总览指标   | 首页 KPI / 攻击趋势 / 防护率(平台聚合) | [`features/overview/backup.ts`](../../console/src/features/overview/backup.ts) |
| `policies` | 策略       | `GET /policies` 的离线只读快照          | [`features/policies/backup.ts`](../../console/src/features/policies/backup.ts) |
| `tools`    | 工具调用   | 工具调用治理流水                         | [`features/tools/backup.ts`](../../console/src/features/tools/backup.ts) |
| `audit`    | 审计会话   | 审计 hash-chain 会话                     | [`features/audit/backup.ts`](../../console/src/features/audit/backup.ts) |
| `supply`   | 供应链扫描 | 组件扫描评级与风险明细                   | [`features/supply/backup.ts`](../../console/src/features/supply/backup.ts) |

> 图标、颜色等**展示态不入文件**——前端按 `key` / `kind` 映射(如 KPI 的 `key → 图标`、来源 `srcType → 图标`),备份只存语义数据。

## 3. 导入契约(上传要带什么)

导入只需上传**这一个 `.json` 文件**。解析器见 [`io.ts`](../../console/src/lib/backup/io.ts) 的 `parseBackup`:

1. **整包前置校验**:顶层必须有 `kind: "fulcrum.backup"`、正整数 `schemaVersion` 与 `resources` 对象。版本不得高于当前 `BACKUP_SCHEMA_VERSION`;未来版本整包拒绝,避免按旧契约误读新字段。否则整包拒绝(提示「不是有效的枢衡备份文件」);非合法 JSON 同样拒绝。
2. **`meta` 全可选**:`instance / note / exportedAt / appVersion` 缺失不影响导入。
3. **`resources` 带哪些桶随意**——这是「上传什么」的关键:
   - 只恢复事件 → 只放 `events`;只恢复看板 → 只放 `overview`;也可都放。
   - **未注册的 `kind`**:安全跳过,不报错(报告里计入 `skipped`,提示「跳过 N 类未知资源」)。
   - **某桶数据校验失败**(字段不符合该资源 schema):只跳过那一桶,其余照常导入——**不整包失败、不污染数据**。
4. **导入报告** `ImportReport`:`{ ok, meta, imported:[{kind,label,count}], skipped:[{kind,reason}], error? }`,前端据此弹 toast(成功/部分跳过/失败)。

最小可导入示例(只带事件、省略 meta):

```json
{
  "kind": "fulcrum.backup",
  "schemaVersion": 1,
  "resources": { "events": [ /* …符合 events schema 的对象… */ ] }
}
```

## 4. 存储、导出与持久化

- **导入后**:数据写入浏览器 `localStorage`,键 `fulcrum.backup.v1`(刷新不丢)。逻辑见 [`context.tsx`](../../console/src/lib/backup/context.tsx) 的 `BackupProvider`。
- **导出**:`buildBackup` 把当前内存中的 `resources` 重新打包成同结构 `.json` 下载(文件名 `fulcrum-backup-<时间戳>.json`),写入 `meta.exportedAt`。
- **载入演示**:`loadDemo` 直接 fetch `public/demo-backup.json` 走同一条导入管线。
- **读取**:页面用 `useResource<T>(kind)` 取某桶数据(未导入时返回稳定空数组)。首页/事件页即据此渲染。

## 5. 扩展:加一种新资源

照 [前端扩展规范](02-前端骨架与扩展规范.md) 的「功能模块插件化」,**信封不动**,三步:

1. 写 `features/<x>/backup.ts`:定义 zod `schema` 与 `ResourceSpec`(`kind/label/schema`)。
2. 在该功能模块 `defineFeature({ … , resources: [xResourceSpec] })` 里挂上(`registerFeatures` 时自动注册)。
3. (可选)在 `public/demo-backup.json` 的 `resources` 里加一桶演示数据。

导入器 / 导出器 / 持久化**零改动**即可识别新桶——这正是「分桶 + 注册表」的目的。

> 真实部署接后端后:备份文件作为**离线交换 / 迁移 / 脱敏分发**格式保留;实时数据则改由事件总线(SSE/WebSocket)推送(见 `features/overview/use-live.ts` 注释)。两者互补,不冲突。
