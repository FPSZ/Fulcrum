# 枢衡可观测性运行契约

> 本文回答什么问题:枢衡当前能观测什么、请求如何关联、日志允许记录哪些字段、哪些能力尚未实现。
> 状态:定稿 v1。
> 范围:应用 HTTP 请求日志、关联 ID、健康检查和现有安全指标;不改变审计 hash-chain 口径。

---

## 1. 能力边界

当前可观测性由三类互补能力组成:

| 能力 | 当前真源 | 用途 | 当前边界 |
|---|---|---|---|
| 应用日志 | `src/fulcrum/observability/` | 排查请求状态、耗时和异常类型 | 标准库 JSON 日志,尚无 OTEL exporter |
| 安全审计 | `AuditSink` 与 hash-chain | 记录安全判定、处置与证据 | 属业务证据链,不是普通访问日志 |
| 安全指标 | `GET /overview/stats` | 从审计事件聚合处置与完整率 | 不是 Prometheus 进程指标 |
| 存活检查 | `GET /healthz` | 判断 API 进程可响应 | 不探测数据库、上游模型和磁盘就绪状态 |

审计链与应用日志职责不同。安全判定必须进入审计链;HTTP 方法、路由、状态码和耗时进入应用日志。不得用普通日志替代审计证据。

---

## 2. 请求关联契约

客户端可以携带:

- `X-Request-ID`:标识一次 HTTP 请求。
- `X-Trace-ID`:标识跨组件调用链。当前只做透传和日志关联,不等同于完整分布式追踪。

服务端处理规则:

1. ID 必须为 1 至 128 位,首字符为字母或数字,其余仅允许字母、数字、`.`、`_`、`:`、`-`。
2. 缺失或非法 ID 不透传,改为服务端生成的 32 位十六进制随机值。
3. 正常响应和由请求体限制器产生的 `400/413` 响应均回写两个响应头。
4. 未捕获异常会写 `http.request.failed` 日志;由于异常响应由框架最外层生成,不承诺该响应一定带关联头。

示例:

```text
X-Request-ID: req-20260731-001
X-Trace-ID: trace.demo:001
```

## 3. 日志 Schema

应用日志为一行一个 JSON 对象。固定字段如下:

| 字段 | 类型 | 说明 |
|---|---|---|
| `timestamp` | string | UTC、ISO 8601、毫秒精度 |
| `level` | string | Python logging 级别 |
| `logger` | string | logger 名称 |
| `event` | string | 稳定事件名或经脱敏的既有日志消息 |
| `request_id` | string | 当前请求关联 ID,存在时写入 |
| `trace_id` | string | 当前调用链关联 ID,存在时写入 |
| `session_id` | string | 业务代码显式绑定时写入,HTTP 中间件不读取 body 猜测 |
| `http_method` | string | HTTP 方法 |
| `http_path` | string | FastAPI 路由模板,例如 `/audit/{session_id}` |
| `status_code` | integer | HTTP 状态码 |
| `duration_ms` | number | 应用内处理耗时 |
| `exception_type` | string | 异常类型名,不写异常参数原文 |

请求完成事件:

```json
{"timestamp":"2026-07-31T08:00:00.000+00:00","level":"INFO","logger":"fulcrum.http","event":"http.request.completed","request_id":"req-1","trace_id":"trace-1","http_method":"GET","http_path":"/healthz","status_code":200,"duration_ms":1.25}
```

## 4. 安全约束

HTTP 可观测性不得记录:

- 请求体、响应体或模型提示词原文。
- Query String。
- `Authorization`、Cookie、API Key 或任意未知 `logging.extra` 字段。
- 未模板化的动态路径参数。

结构化 formatter 只接受固定白名单字段。既有日志消息还会经过 `core.redaction.redact()` 再输出。未知路由统一记为 `<unmatched>`,避免把攻击者构造的原始路径写入日志。

---

## 5. 失败模式与降级

| 场景 | 行为 |
|---|---|
| 客户端 ID 非法 | 替换为随机 ID,不返回原值 |
| 请求在路由匹配前结束 | `http_path=<unmatched>` |
| 业务返回 4xx/5xx 响应 | 写完成事件与实际状态码 |
| 未捕获异常 | 写失败事件、异常类型和耗时,随后交框架处理 |
| 日志已由宿主配置 | `configure_logging()` 保持幂等,不重复添加 handler |
| Uvicorn 自身访问日志 | 仍由 Uvicorn 管理;本契约只保证 `fulcrum.*` 应用日志 |

## 6. 未解决问题

以下仍是计划,不能写成已落地:

- OTEL trace/span exporter 与 W3C `traceparent`。
- Prometheus/OpenMetrics 进程指标和直方图。
- 区分 liveness/readiness,并对 SQLite、上游智能体、模型端点做依赖探测。
- 跨进程日志采集、留存、轮转和告警规则。

## 中间件顺序契约(评审 #126 补)

注册顺序固定为:`install_request_observability` 先于 `_limit_body_size`(FastAPI/Starlette 后注册者先执行,即**体积限制先挡 413,可观测中间件在外层**)——被 413 拒绝的请求仍留一条含关联 ID 的访问日志(`http.request.completed`,status=413),满足"异常路径可定位"。此顺序为本契约的一部分,调整须同步更新本节。
