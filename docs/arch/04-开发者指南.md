# 枢衡 Fulcrum · 开发者指南(如何加功能)

> 本文回答:**在枢衡骨架上加一个能力,具体改哪些文件、写什么、怎么验证。**
> 状态:配套 [后端骨架与扩展规范](01-后端骨架与扩展规范.md)。先读那篇懂分层,再用本篇照着加功能。
> 一句话:**所有功能都在 `src/fulcrum/capabilities/` 下"实现接口 + 注册 + 配置启用",不碰 `core/`。**

---

## 0. 黄金法则

| 你要做的 | 在哪 |
|---|---|
| 加一个检测器 / 工具 / 策略 / 扫描器… | `src/fulcrum/capabilities/<类型>/` 新建文件 |
| 让它生效 | `src/fulcrum/config/fulcrum.yml` 加一行;`capabilities` 的 `load_builtin_capabilities()` 里加一行 import |
| 加测试 | `tests/` 新建 `test_*.py` |
| **不要动** | `src/fulcrum/core/**`(域类型/接口/注册表/管线)、`src/fulcrum/app.py`、`pyproject.toml` 的 import-linter 契约 |

> 想改 `core/` 的接口或管线?那是**架构变更**,先找架构负责人评审,别自己改——CI 的依赖铁律也会拦。

---

## 1. 通用三步(任何能力都一样)

```
第 1 步 实现接口   在 capabilities/<kind>/your_impl.py 写一个类,实现对应 port 的方法
第 2 步 注册       类上加 @capability("<kind>", "<name>")
第 3 步 启用       load_builtin_capabilities() 里加一行 import;config/fulcrum.yml 按 <name> 启用
（第 4 步 测试      tests/ 加单测;本地跑 pytest / ruff / lint-imports 全绿）
```

`<kind>`(能力类型)只有这几种,不可新增:
`labeler / detector / attributor / risk_scorer / chain_analyzer / policy / tool / executor / scanner / model / audit`。

## 2. 完整示例:加一个检测器

需求:检测输入里是否出现 base64 长串(可疑外带)。

**① 实现** `src/fulcrum/capabilities/detectors/base64_blob.py`
```python
from __future__ import annotations

import re

from ...core.domain import Context, Finding, SourceSpan
from ...core.registry import capability

_B64 = re.compile(r"[A-Za-z0-9+/]{60,}={0,2}")


@capability("detector", "base64_blob")          # ② 注册
class Base64BlobDetector:
    name = "base64_blob"

    def detect(self, spans: list[SourceSpan], ctx: Context) -> list[Finding]:
        findings: list[Finding] = []
        for span in spans:
            if _B64.search(span.excerpt):
                findings.append(
                    Finding(kind="suspicious_blob", score=0.5,
                            evidence={"source_id": span.source_id})
                )
        return findings
```

**③ 启用**
- 在 `src/fulcrum/capabilities/__init__.py` 的 `load_builtin_capabilities()` 函数体里加一行:
  ```python
  from .detectors import base64_blob  # noqa: F401
  ```
- `src/fulcrum/config/fulcrum.yml` 的 `detectors:` 列表加一项:
  ```yaml
  detectors:
    - keyword_rules
    - base64_blob
  ```

**④ 测试** `tests/test_base64_blob.py`,跑 `pytest` 验证。

完成——**没有改 `core/`,没有改 `pipeline.py`,没有改别人的代码。**

## 3. 各能力接口速查(照着实现 `...` 即可)

> 类型一律从 `fulcrum.core.domain` 导入;装饰器从 `fulcrum.core.registry` 导入。

| kind | 类需实现的方法 | 配置位置(fulcrum.yml) |
|---|---|---|
| `labeler` | `label(self, req: ModelRequest) -> list[SourceSpan]` | `labeler:`(单个) |
| `detector` | `name`;`detect(self, spans, ctx) -> list[Finding]` | `detectors:`(列表) |
| `attributor` | `attribute(self, intent, spans, ctx) -> Attribution` | `attributor:`(单个) |
| `risk_scorer` | `score(self, intent, ctx) -> float` | `risk_scorer:`(单个) |
| `chain_analyzer` | `analyze(self, session_trace, ctx) -> list[Finding]` | `chain_analyzer:`(单个) |
| `policy` | `decide(self, intent, ctx) -> PolicyDecision` | `policy:`(单个) |
| `tool` | `name`;`call(self, arguments: dict, ctx) -> ExecResult` | `tools:`(列表) |
| `executor` | `execute(self, tool, intent, ctx) -> ExecResult` | `executor:`(单个) |
| `scanner` | `scan(self, manifest: dict, ctx) -> ScanReport` | `scanner:`(单个) |
| `model` | `async chat(self, req: ModelRequest) -> ModelResponse` | `model:`(单个) |
| `audit` | `append(event) -> AuditEvent`;`events(session_id)`;`verify_chain(session_id)` | `audit:`(单个) |

> 接口完整签名见 `src/fulcrum/core/ports/__init__.py`。**不要改那个文件**,只照着实现。

## 4. 本地验证(提交前必须全绿)

```powershell
uv sync --extra dev          # 首次:装依赖
uv run pytest -q             # 测试
uv run ruff check src tests  # lint
uv run ruff format src tests # 格式化
uv run lint-imports          # 依赖方向(改错层会红)
```

或 `pre-commit install` 后,每次 `git commit` 自动跑 ruff + 依赖检查。

## 5. 常见问题

- **报"未找到能力实现"**:`fulcrum.yml` 里写的 `<name>` 没注册——检查 `@capability` 的 name、以及 `load_builtin_capabilities()` 是否 import 了你的模块。
- **`lint-imports` 失败**:你大概在 `capabilities/` 里 import 了 `adapters` 或 `fastapi`——能力实现只能依赖 `core`。
- **想新增一种能力类型(kind)**:不行,需架构评审;现有 11 种覆盖四目标,先归到合适的 kind。
