## 4. 合并门槛

1. 分支必须 rebase 到最新 `origin/dev`，并解决冲突；不得以旧分支的整体文件覆盖新基线。
2. 通过与变更范围匹配的单元、接口和安全回归测试；高风险执行器、配置热替换和审计路径必须有失败场景测试。
3. 涉及指标的 PR 必须记录数据集版本、运行命令、模型/端点、策略和生成时间，并与主结果分开保存。
4. 全量评测不出现主基线召回、FPR、Utility 或处置准确率回退；新检测器需要提供按攻击类型和闸门分域结果。
5. 安全边界变更必须说明 fail-closed/fail-safe 行为、旁路风险和生产部署限制。
