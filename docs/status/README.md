## 1. 目录职责

`docs/status/` 是当前实现与验证结果的快速接手入口,用于减少重复全仓阅读成本。它不替代规划、架构、接口和评测正式文档,也不把计划写成已经完成的事实。

建议按以下顺序阅读:

1. 仓库根目录的 [AGENTS.md](../../AGENTS.md),确认长期协作、安全和事实优先级规则。
2. 本页,掌握项目真实成熟度和状态页使用方法。
3. 按任务阅读对应状态页:
   - [01-前端状态.md](01-前端状态.md)
   - [02-后端状态.md](02-后端状态.md)
   - [03-文档状态.md](03-文档状态.md)
   - 04-评测状态.md(评测口径定稿后补充)
4. 再进入状态页链接的源码、架构或评测正式文档核对细节。

## 3. 状态标记

| 标记 | 含义 |
|---|---|
| 已实现 | 当前代码存在真实执行路径,并有测试或可运行验证支撑。 |
| 部分实现 | 核心路径存在,但范围、默认配置、持久性或安全强度有限。 |
| 可选能力 | 代码存在,但默认装配未启用,不能当作开箱基线。 |
| 规划中 | 文档提出目标,当前代码尚未兑现或证据不足。 |
| 历史状态 | 对过去提交、评测或阶段有效,不能覆盖当前代码事实。 |
| 待验证 | 尚无足够测试、实测或正式结果支撑。 |

## 5. 使用与维护规则

- 状态页是“特定日期快照”,不能凌驾于当前代码、当前评测产物和更高优先级事实源。
- 修改相关模块后,应同步更新对应状态页的快照日期、代码基线、实现状态、风险和验证结果。
- 状态页只写摘要与导航;详细接口契约继续放在 `docs/arch/`,指标定义和实验记录继续放在 `docs/eval/`。
- 已知缺口关闭后,必须附上代码、测试或结果文件证据,不能只删除风险描述。
- 不在状态页保存密钥、Cookie、真实敏感数据、未脱敏日志或可直接攻击真实系统的 payload。
- 若状态页与赛题原文、定稿规划、定稿架构或定稿评测文档冲突,按 [AGENTS.md](../../AGENTS.md) 的事实优先级处理并显式记录冲突。
