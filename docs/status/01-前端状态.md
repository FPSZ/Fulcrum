## 1. 总体判断

前端已经不是静态演示壳。主要运营页面均存在真实后端请求路径,无数据时使用空态或显式标注的演示备份。当前成熟度适合原型演示、功能验收和联调,但仍缺少可执行的 ESLint 门禁,少量计划中控件尚未接通,AI 助手流式输出与浏览器本地留存需要按政企敏感数据要求进一步收紧。

### 3.2 AI 操作助手

助手页已经接入后端 function-calling Agent,支持:

- 读取型操作自动执行。
- UI 操作转为前端导航或界面指令。
- 写操作先生成提案,再由用户确认。
- 确认后执行、返回撤销句柄。
- 工具列表按 RBAC 过滤,执行点由后端再次校验。
- 工具较多时通过 `search_operations` 渐进式发现。
- SSE 流式答复和 AbortController 中止。
- 会话偏好与浏览器端对话副本。

入口代码见 [assistant feature](../../console/src/features/assistant/) 和后端 [AssistantAgent](../../src/fulcrum/adapters/assistant/agent.py)。

## 4. 数据真实性边界

- 主要页面优先读取后端 API,不应再沿用“控制台整体为静态 mock”的历史结论。
- [console/README.md](../../console/README.md) 中“趋势图和事件流是合成动画”的描述已经落后于当前实现。
- `console/public/demo-backup.json` 是显式演示备份,不应与实时后端数据混淆。
- 总览趋势是由事件时间戳在前端分桶生成,不是独立时序数据库或流处理系统。
- 浏览器 `localStorage` 会保存助手会话相关内容,可能包含模型答复、事件摘要或操作提案;它是浏览器本地副本,不具备 HttpOnly Cookie 的保护属性。

## 5. 已知风险与缺口

### P0:流式输出先发送、后检测

后端 `AssistantAgent.run_stream()` 在模型生成过程中先发送 `delta`,完整文本形成后才执行出口检测。若模型输出敏感内容,最终 `done` 事件即使替换为拦截文案,先前 SSE 字节也无法撤回。前端中止能力不能消除这一问题。

这与核心模型端口“完整缓冲、检测通过后再放行”的安全边界不一致。修复方向应是服务端缓冲、分块安全检测或带可证明边界的延迟流式协议,不能只在前端覆盖最终答复。

### P1:敏感内容本地留存

助手会话进入 `localStorage` 后,同源脚本、浏览器插件、共享终端和运维取证都可能接触这些内容。生产环境需要明确保留范围、TTL、清除入口和敏感字段过滤策略。

### P1:质量门禁不完整

`package.json` 声明 `npm run lint -> eslint .`,但 `devDependencies` 中没有 ESLint,仓库也没有可用配置。本地和 CI 都无法把该脚本作为稳定门禁。

### P2:少量未接通控件

- 事件详情“查看完整链”按钮有样式但没有执行行为。
- “批量处置”按钮保持禁用。
- 这类控件应显式标记“规划中”或暂时移除,避免演示时被理解为已完成能力。

## 7. 后续优先级

4. 接通或移除事件页死控件,统一标记规划中能力。
