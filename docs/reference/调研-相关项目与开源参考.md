# 调研:智能体安全相关项目与开源参考

> 本文回答:**业界已有哪些相关项目?它们各自解决什么痛点?哪些可以参考学习?优缺点是什么?枢衡的差异化空间在哪?**
> 状态:调研底稿 v1（2026-06-14，历史参考）；本文用于架构取舍，不代表当前实现或评测结论。当前实现状态见 [`../plan/03-进度看板.md`](../plan/03-进度看板.md)。
> 用途:为枢衡的技术架构设计提供"参考标杆"与"避坑清单",并明确差异化定位。

## 1. 调研方法与范围

- 按枢衡四大能力分域检索:① 输入侧攻击识别 ② 工具调用安全管控 ③ 供应链检测 ④ 评测与审计,外加"审计/可观测"与"国内政企生态"两个横切面。

- 标注口径:**🟢 强相关可深度借鉴 / 🟡 部分可借鉴 / ⚪ 背景参考**。
- 注:开源项目的 star 数、维护状态等会随时间变化,选型落地前需二次核实仓库活跃度与许可证。

## 2. 行业痛点总览(从调研中提炼)

调研印证了榜题判断,并补充了更具体的痛点:

1. **防护单点化、各自为政**:市面工具大多只做"检测"或"网关"或"评测"或"可观测"中的**某一段**,缺少贯通「评测—防护—审计—运营」的闭环。
2. **守不住"间接注入"**:能拦直接提示注入,但**对来自网页/文档/工具返回值的间接指令污染**识别弱;且缺乏"污点追踪"——难以回答"这次危险工具调用的参数到底源自哪条不可信输入"。
3. **工具调用缺乏细粒度管控与人工审批**:多停留在"允许/拒绝"或正则规则,缺**分级权限 + 关键操作人工审批(HITL) + 异常任务链阻断**。
4. **审计停留在"可观测",不等于"可追溯"**:有调用链 tracing,但缺**防篡改证据链、责任可追溯、分级处置**(政企刚需)。
5. **评测基准偏英文、偏通用**:AgentDojo/InjecAgent 等是英文、固定场景,**缺政企中文场景与可量化审计证据输出**。
6. **供应链检测偏"静态签名"**:MCP 扫描多看 manifest 文本特征,**行为/依赖/动态分析弱**。
7. **守护方自身被攻破**:guardrail 本身可被绕过(已有多篇"evasion attacks against guardrails"论文),提示防护要纵深、要可评测。
8. **国内生态偏内容合规**:国产方案多聚焦内容安全/合规审计,**工具调用与供应链安全相对薄弱**。

> 这八条痛点,正是枢衡"一体化闭环 + 污点贯穿 + 审批分级 + 可信审计 + 政企中文评测"差异化的依据。

## 3. 分域项目盘点

### 域① 输入侧攻击识别(对应目标 1)

| 项目 | 性质 | 解决的痛点 | 优点(可借鉴) | 缺点 / 局限 |
|---|---|---|---|---|
| 🟢 **Meta LlamaFirewall** | 开源框架(Purple Llama) | 智能体全生命周期防护:注入/越狱、目标劫持、不安全代码 | 分层防御范式好;`PromptGuard 2` 小模型低延迟(称 1% 误报下 97.5% 召回);理念与枢衡①②③高度同构,是**头号参考标杆** | `AlignmentCheck` 为实验性且依赖强 LLM(成本/延迟);模型偏英文;**无细粒度工具权限/审批、无审计闭环、无供应链 manifest 扫描** |
| 🟢 **Rebuff** | 开源(Apache-2.0) | 提示注入检测 | **多方法融合**:启发式 + LLM 分类 + 向量库(已知攻击)+ canary word;**自硬化**(从命中样本学习) | 依赖外部模型、有延迟;项目维护活跃度需核实;仅检测、不管控 |
| 🟢 **LLM Guard**(Protect AI) | 开源(MIT) | 输入+输出统一扫描 | **scanner 套件最全**:注入、PII、毒性、越狱等,可纯自托管(隐私友好) | 仅"扫描器"层,**不涉及工具调用管控/审计闭环**;规则需调参 |
| 🟡 **Vigil** | 开源(MIT) | 轻量注入扫描 | 多扫描器(YARA + Transformer + 向量库 + 响应相似度 + canary),易集成 | 偏轻量、维护一般;仅检测 |
| 🟡 **NeMo Guardrails**(NVIDIA) | 开源 | 可编程"对话护栏" | 成熟、生态广;`Colang` DSL 可编程、模型无关、可解释;有 NemoGuard 系列模型 | 偏**对话式**输入输出;配置复杂、有延迟;对**工具调用数据流/供应链**不深入 |

### 域② 工具调用安全管控(对应目标 2)—— 枢衡重点深做域

| 项目 | 性质 | 解决的痛点 | 优点(可借鉴) | 缺点 / 局限 |
|---|---|---|---|---|
| 🟢 **Invariant Guardrails**(已被 Snyk 收购) | 开源 + 商业 | 智能体/MCP 行为管控 | **与枢衡②最像**:以 **Gateway 透明代理**插在 App 与 MCP/LLM 之间,无侵入;Python 风格**策略 DSL**;能做**轨迹语义分析**,识别"未授权工具序列""数据外泄""异常决策" | 写规则需要专业知识;被 Snyk 收购后开源走向待观察;偏通用/英文;**缺关键操作人工审批、缺审计级证据链、缺量化评测** |
| 🟡 **LlamaFirewall · AlignmentCheck** | 开源 | 行为对齐审计 | 用 CoT 推理审计"智能体动作是否仍符合用户目标",**在动作执行前拦截目标劫持** | 实验性;依赖强 LLM,成本/延迟高 |
| 🟡 **AgentSpec**(ICSE'26 论文) | 学术原型 | 智能体运行时强制 | 可定制的**运行时强制 DSL**,面向安全可靠的 LLM 智能体,学术上系统化 | 研究原型,工程成熟度/生态有限 |
| ⚪ "Design Patterns to Secure LLM Agents" / Reversec | 实践文章 | 安全设计模式 | 系统梳理**作用域与权限最小化、trust zone、隔离边界、kill switch** 等可落地模式 | 是方法论,非现成工具 |

> 关键借鉴:Invariant 的"**透明代理 + 策略 DSL + 轨迹语义分析**"是枢衡②的最佳蓝本;枢衡需在其上补"**分级权限 + 人工审批 + 异常任务链阻断 + 审计证据**"。

### 域③ 供应链检测(对应目标 3)—— 枢衡轻量做全域

| 项目 | 性质 | 解决的痛点 | 优点(可借鉴) | 缺点 / 局限 |
|---|---|---|---|---|
| 🟢 **mcp-scan**(Invariant) | 开源 | MCP 工具投毒/换包 | **静态分析 MCP manifest**:检测工具描述里的注入式指令、tool-poisoning 模式;**版本间 manifest 变更检测(rug-pull)**;可入 CI | 仅 MCP、仅 manifest 静态特征;**行为/依赖/动态分析弱** |
| 🟢 **Cisco MCP Scanner** | 开源 | AI 智能体供应链 | 厂商级开源,补"智能体供应链"扫描空白,可作对照 | 同样以 MCP 为中心 |
| 🟡 **LlamaFirewall · CodeShield** | 开源 | 生成/扩展代码安全 | **Semgrep + 正则**的在线静态分析,语法感知、支持 8 种语言、可扩展规则 | 偏"代码漏洞",非"恶意逻辑/隐蔽外联"专门检测 |
| 🟡 **MCPGuard / MCP 威胁建模论文** | 学术 | MCP server 漏洞自动检测 | 提供**威胁模型与控制项清单**,可作枢衡③的检测维度参考 | 多为论文/原型 |

> 现实警示:有研究对 11 个 MCP 注册表投毒成功 9 个,6 个生产平台被远程执行——供应链风险真实且高发,枢衡③即便轻量也要做出"扫描+评级+CI 可用"。

### 域④ 评测与审计溯源(对应目标 4)—— 枢衡串联支撑域

**评测 / 红队基准:**

| 项目 | 性质 | 优点(可借鉴) | 缺点 / 局限 |
|---|---|---|---|
| 🟢 **AgentDojo** | 开源基准 | **智能体注入评测金标准**:124 安全任务 + 629 攻击任务、4 场景、74 工具;指标含 **ASR(攻击成功率)与 Utility(受攻击下任务完成度)** | 英文、固定场景,**非政企**;评的是被攻击智能体,非防护系统 |
| 🟢 **InjecAgent** | 开源数据集 | 1000 条触发"未授权工具调用"样例,含 Base/Enhanced 两档 | 静态;仅"直接危害/数据窃取"目标 |
| 🟡 **Agent Security Bench (ASB)** | 开源(ICLR'25) | 覆盖更广的智能体攻防基准 | 通用、英文 |
| 🟡 **AgentHarm** | 开源基准 | 评"对有害任务的拒绝能力" | 侧重内容有害,非工具越权 |
| 🟡 **AgentAuditor** | 学术 | **人类水平安全评估**:用 LLM-as-judge 做轨迹审计 | 原型,需适配 |
| 🟢 **garak**(NVIDIA) | 开源扫描器 | LLM 漏洞探针扫描,**JSONL 结构化结果便于回归对比** | 偏**模型级**,非智能体工具链级 |
| 🟢 **PyRIT**(Microsoft,MIT) | 开源框架 | 红队**攻击编排框架**:多轮对话、越狱库、自动打分;扩展性强 | 是框架非基准,需自建场景 |

**审计 / 可观测 / 治理:**

| 项目 | 性质 | 优点(可借鉴) | 缺点 / 局限 |
|---|---|---|---|
| 🟢 **Langfuse** | 开源(可自托管) | **现成 tracing 骨干**:记录请求全生命周期(LLM 调用、检索、工具执行、时延、输入输出);兼容 OpenTelemetry | **observability ≠ 审计**:无防篡改证据链、无责任溯源/分级处置、无安全策略 |
| 🟡 **OpenLLMetry / OTEL** | 开源标准 | 行业向 OTEL 收敛,枢衡审计宜兼容此标准 | 仅遥测标准 |
| ⚪ **OWASP LLM / Agentic / Agentic Skills Top 10** | 标准/框架 | **权威风险分类法**,可直接用来搭枢衡"多维度评测体系"骨架;强调"签名、不可变审计日志""记录每个特权动作" | 是框架不是工具 |
| ⚪ **AAGATE / NIST AI RMF 对齐治理** | 学术平台 | 合规治理映射参考(政企看重) | 偏治理,落地需裁剪 |

### 横切:国内政企生态(⚪ 背景参考)

| 项目/方案 | 优点 | 缺点 / 局限 |
|---|---|---|
| 安恒"大模型安全防护系统"等商业方案 | **中文场景、内容合规、用户级会话审计**,有政务落地案例 | 偏内容安全/合规;**工具调用、供应链安全较弱**;闭源,难复现 |
| 国产 `llm-security` 类开源 | 轻量 BERT 分类器识别注入 + 推理过程审计 + 自定义规则层 | 偏检测;成熟度/维护需核实 |
| "多轮会话安全检查层"实践 | 识别跨轮次累积风险、**延迟触发型注入**,对长对话有效 | 偏内容,非工具/执行安全 |

## 4. 重点标杆深读:学什么、避什么

### 4.1 LlamaFirewall(Meta)—— 枢衡①②③ 的形态蓝本

- **学**:三层分工(注入检测器 `PromptGuard` + 行为对齐审计 `AlignmentCheck` + 代码静态分析 `CodeShield`)+ "低延迟小模型在线拦截"的工程取向。这正是枢衡"防护内核"的合理骨架。
- **避/补**:它**没有**细粒度工具权限与人工审批、**没有**审计证据链与溯源、**没有**供应链 manifest 扫描、模型**偏英文**。→ 枢衡用"一体化闭环 + 审批分级 + 中文政企"补齐。

### 4.2 Invariant Guardrails —— 枢衡② 的最佳工程参考

- **学**:**透明代理(Gateway)无侵入插入** + **策略 DSL** + **对智能体轨迹做语义分析**(识别未授权工具序列、数据外泄)。配套 `mcp-scan` 覆盖供应链——这套"代理 + 策略 + 轨迹分析 + 供应链扫描"组合,与枢衡蓝图几乎对位。
- **避/补**:规则编写门槛高、被收购后开源走向不明、缺"关键操作人工审批/分级处置"、缺"量化评测出分"。→ 枢衡把**审批工作流、防篡改审计、政企中文评测**做成自己的护城河。

## 5. 共性优缺点与空白(枢衡的差异化空间)

**业界共性优点(枢衡应直接站在肩膀上,不重复造轮子):**
- 透明代理/网关式无侵入接入(Invariant)。
- 分层防御 + 低延迟小模型在线检测(LlamaFirewall/PromptGuard)。
- 现成 tracing 骨干与 OTEL 标准(Langfuse/OpenLLMetry)。
- 现成攻击数据集与红队框架(AgentDojo/InjecAgent/PyRIT/garak)做评测底座。
- 现成 MCP 供应链扫描器(mcp-scan/Cisco)做③的起点。

**业界共性空白(枢衡的差异化抓手):**

| 空白 | 枢衡的差异化做法 |
|---|---|
| 四段割裂,无闭环 | **「评测—防护—审计—运营」一体化闭环**——核心卖点与创新点 |
| 间接注入难溯源 | **跨多源输入的污点/溯源贯穿**:为输入打"信任标签",追踪其是否流入高危工具调用 |
| 工具调用缺审批 | **分级权限 + 关键操作人工审批(HITL)+ 异常任务链阻断** |
| 审计≠可追溯 | **防篡改证据链 + 责任可追溯 + 分级处置**(政企合规刚需) |
| 评测偏英文通用 | **政务办公中文攻击样例集 + 可量化审计证据输出** |
| 供应链偏静态签名 | 在 manifest 静态之外补**行为/依赖/调用链**轻量分析 + **安全评级** |

## 6. 给枢衡的可执行结论

**借鉴清单(站在肩膀上):**
1. 接入形态学 Invariant 的**透明代理/网关**,保证"无侵入、兼容 OpenClaw 类"。
2. 防护内核学 LlamaFirewall 的**分层 + 小模型低延迟**;注入检测可参考 Rebuff 的**多方法融合 + canary + 自硬化**。
3. 审计底座兼容 **OTEL/Langfuse**,在其上加"安全语义 + 防篡改证据链"。
4. 评测复用 **AgentDojo / InjecAgent** 做对照基线,用 **PyRIT/garak** 做红队,自建**政企中文样例集**做主场。
5. 供应链以 **mcp-scan** 思路为起点,补行为/依赖分析与评级。

**避坑清单:**
- 不做"只检测不管控"的单点;不停留在"可观测"冒充"审计"。
- 警惕 guardrail 自身被绕过——防护要纵深、且**用自己的评测域证明有效性**。
- 不照搬英文模型/基准,**中文政企适配**是得分点也是难点,需提前留预算。

**一句话差异化定位:** 业界已有"检测器、网关、扫描器、基准、可观测"等优秀**零件**,但**没有把它们串成面向政企的闭环**。枢衡的价值不在重造零件,而在做出那条**贯通且可量化、可审计、可追溯的一体化链路**。
