## 摘要(Abstract)〔约 1 页〕

大模型应用正由问答式系统演进为具备检索、记忆、工具调用、文件处理、跨系统联动与自动执行能力的**智能体系统**,在政务办公等高价值场景加速落地的同时,带来了区别于传统软件与普通大模型应用的四类新型安全风险:输入侧污染、供应链风险、越权与泄露、过程不可控。行业普遍缺少兼顾「**评测—防护—审计—运营**」的一体化关键技术。

本作品提出并实现 **枢衡(Fulcrum)**——一个**无侵入旁挂**于智能体外侧的全生命周期安全中台。它以**透明安全网关 + 策略驱动管线 + 来源归因总线**为主干,把智能体「输入 → 决策 → 工具调用 → 执行 → 输出」的全过程纳入管控,并持续产出防篡改审计证据与可量化评测指标,兼容 OpenClaw 类及其他具备工具调用能力的智能体应用。

四大能力对应榜题四个技术目标:①多源输入攻击识别与分级评估;②工具调用「感知—决策—调用—执行」全流程安全管控与异常任务链阻断;③插件/Skill/脚本供应链安全检测与评级;④多维度安全评测与防篡改审计溯源。

在自建的 200 条对抗攻击样例库(对齐 OWASP LLM Top10:2025 / MITRE ATLAS)上,枢衡将攻击成功率(ASR)由基线 **100% 降至 1.2%(降幅 98.8%)**,召回 **98.8%**、精确率 **100%**、F1 **99.4%**、误报率 **0%**、正常任务可用性 **100%**、处置准确率 **92.5%**;供应链恶意组件召回 **100%**、溯源命中率 @1/@3 均 **100%**;审计完整率与 hash-chain 防篡改通过率均为 **100%**;网关侧 P95 净增延迟 **3.0ms**。真模型在环端到端实测(MiMo 走完整网关)中 8/8 攻击全部被中和、零漏过。全部结果一键可复现。

**关键词**:大模型智能体安全;提示注入;工具调用管控;供应链检测;审计溯源;安全评测;纵深防御

## 第 1 章 问题分析〔约 4 页〕

### 1.1 背景:从「大模型应用」到「智能体系统」的安全范式迁移

智能体相较传统大模型应用新增了**外部世界的读写能力**:检索网页/知识库、读写文件、调用系统命令、联动跨系统接口、保留长期记忆并据此自动决策与执行。这使攻击面从「模型输出内容」扩展到「模型驱动的真实动作」——一次被污染的决策可能直接落地为越权读写、数据外泄或不可逆破坏。

### 1.2 四类新型安全风险(对应榜题背景)

| # | 风险类别 | 典型攻击 | 后果 |
|---|---|---|---|
| 1 | **输入侧污染** | 恶意提示注入、间接指令污染(网页/文档/RAG 夹带)、越狱诱导、知识投毒 | 劫持模型决策 |
| 2 | **供应链风险** | 恶意 Skill/插件/脚本、依赖混淆、安装期钩子、隐蔽外联 | 引入后门与高危调用链 |
| 3 | **越权与泄露** | 高权限文件读写、系统命令执行、SSRF/接口联动、敏感量批量外泄 | 越权操作与数据泄露 |
| 4 | **过程不可控** | 缺乏运行过程监测、审计溯源、分级处置 | 难以满足「安全可控、过程可审计、责任可追溯」 |

### 1.3 行业空白:缺少「评测—防护—审计—运营」一体化关键技术

现有方案多为**单点能力**(注入分类器、网关、可观测平台各自为政),缺少把"识别—管控—取证—出分"贯穿成闭环、并能输出**可量化指标 + 可追溯证据**的一体化中台。这正是本作品要补的空白。

### 1.4 政企场景的硬约束

无侵入兼容(不改造被保护智能体)、私有化可离线(数据不出域、模型可插拔默认国产/本地)、低延迟在线拦截、责任可追溯(防篡改证据链 + 来源归因)。

### 1.5 目标场景:政务办公助手(英雄场景)

选定**政务办公助手**作为跑通整条链路、录制演示的英雄场景:它天然同时涉及文件读写、系统命令、外部接口、知识库检索、历史记忆——四类攻击面一次性覆盖,可在同一条 Demo 链路里展示「攻击 → 识别 → 阻断 → 审计 → 评测出分」完整闭环。其它场景(知识检索问答、业务流程办理、运维协同)作兼容性佐证。

## 第 2 章 技术路线〔约 5 页〕

### 2.1 总体架构:透明安全网关 + 策略驱动管线 + 来源归因总线

枢衡作为**透明安全网关(Transparent Security Gateway)**旁挂在智能体与外部世界之间,首要覆盖 **OpenAI 兼容 LLM API + MCP 工具**两类边界,非 MCP 工具(本地函数/浏览器驱动/文件 SDK)经**工具适配器**统一纳管。对确实绕过网关的路径,不假装能拦截,而是在审计侧检测「无网关记录的行为」并告警(诚实声明边界,见 §2.5)。

```
1. 智能体请求(用户输入 + 网页/文档/检索/记忆)
   └► C1 接入层截获 ─► C2a 输入扫描 + 来源打标(写入来源归因总线)
2. 模型产出"工具调用意图"
   └► C2b 工具风险评分 + 任务链污点分析 ─► C3 策略中心判定(含归因置信度)
3. 分级处置 C4: allow 放行 | sanitize 净化改写 | approve 转人工 | block 阻断
4. 放行的高危调用 ─► C4x 沙箱执行器(新工具先过 C5 供应链扫描)
5. 模型回复 ─► 出口检测(screen_output):敏感/危险内容 放行/复核/打码拦截
6. 全过程写入 C6 防篡改审计链(含带置信度的归因链路)
7. 评测模式:C6 评测引擎回放样例,统计 ASR/误报漏报/阻断率/审计完整率/溯源命中率
8. C7 控制台:事件 / 审批 / 审计溯源 / 评测报告 / 策略 / 供应链 / 工具网关
```

> 图源 `docs/arch/diagrams/architecture-overview.d2`(D2 DSL,可版本化维护);PDF 排版时按页宽缩放。

### 2.2 纵深防御:三道对称闸门

枢衡的防护不是单点,而是沿数据流布设**三道闸门**,任一层独立生效、逐层兜底:

| 闸门 | 入口 | 职责 |
|---|---|---|
| **输入闸门** | `screen_input` | 入口判恶意 → 拦截/审核/放行 |
| **工具治理** | `evaluate_intent` | 工具调用判越权/高危 → allow/sanitize/approve/block |
| **出口检测** | `screen_output` | 回复判敏感/危险 → 放行/复核/打码拦截 |

三道闸门均落审计、口径对称。第 6 章按闸门分域量化了每层的实际贡献度。

### 2.3 组件分解(对应四目标)

| # | 组件 | 职责 | 目标 |
|---|---|---|---|
| C1 | 接入层 | LLM 代理(OpenAI 兼容)、MCP 代理、非 MCP 适配器 | 全局入口 |
| C2a | 输入威胁检测 | 多源注入/越狱/投毒/间接污染扫描 + 来源打标 | ① |
| C2b | 工具调用管控 | 工具风险评分 + 任务链污点分析 | ② |
| C3 | 策略中心 | 声明式 YAML 策略 + 风险分级 | ①② |
| C4 | 审批与分级处置 | allow / sanitize / approve(HITL) / block | ② |
| C4x | 沙箱执行器 | 高危工具受限执行(路径/命令/外联/超时/体积边界) | ② |
| C5 | 供应链扫描器 | manifest + 权限 + 外联依赖 + 安装钩子 → 评级 | ③ |

### 2.5 失败模式与降级(fail-closed 原则)

企业级可信度的关键是诚实声明边界:智能体绕过代理直连模型 → 部署侧限制出口 + 审计侧检测告警;工具不走 MCP → 适配器纳管,无法适配者标"不可控来源"、策略收紧;流式中断 / 审批超时 / 审计写入失败 / 策略不可用 → 一律 **fail-closed**(高危默认阻断并留痕);检测误杀(高 FPR)→ 分级处置(净化/审批优先于阻断)+ 控制台一键放行 + 样本回流。**总原则:安全关键路径 fail-closed,可用性路径 fail-open 但留痕。**

### 2.6 工程实现与技术栈

后端 Python 3.11+,FastAPI + uvicorn + httpx(async);轻量六边形架构(`core` 纯领域 ← `capabilities` 端口实现 ← `adapters` ← `app`),依赖方向由 import-linter 三契约 CI 强制;前端 React + TS + Vite + 自研组件库 + 功能模块插件系统;uv + Docker Compose 一键部署。代码质量门:ruff + pyright + import-linter + pytest 全绿。

## 第 3 章 算法设计〔约 6 页〕

### 3.1 目标①:多源输入攻击识别与分级评估

**3.1.1 来源打标(确定性强)**
`role_trust` 标注器为每段输入打 `信任级别`(可信/半可信/不可信)+ `来源类型`(用户/网页/文档/检索/记忆/工具返回/系统),并抽取嵌入来源(`---BEGIN/END---` 等 RAG 框架定界标记 → 激活检测器对间接来源加权)。这一步可严格落地。

**3.1.2 多源规则检测 + 解码复扫**
`keyword_rules` 检测器对七类风险(注入/越狱/外发/敏感文件/命令执行/投毒/结构化 PII 泄露)按**来源信任级 × 直接/间接加权**评分,输出 low~critical 分级。关键加固:**匹配前归一化**(去空白/casefold/HTML 实体解码) + **解码复扫**(Base64/Hex 还原后复检,抓编码绕过) + `pii_leak` 按命中条数升级(1 条 0.4 多属正常 → ≥3 条 0.85 critical,拦"市民名册原样吐出"类批量泄露)。

**3.1.3 证据化归因(带置信度,非形式化 taint)**
LLM 是非透明变换,无法严格证明某工具参数一定来自某段不可信输入。`evidence` 归因器以**多证据加权**给出置信度:参数片段原文是否出现在来源摘录(去壳 scheme/引号/尾斜杠归一)× 来源信任权重 × 匹配强度 → `derived_from_sources` + 置信度。审计时可反查"危险调用 ← 高可能由哪条不可信输入引发",输出**可解释的带置信度归因链**。

### 3.2 目标②:工具调用「感知—决策—调用—执行」全流程管控

**3.2.1 工具风险评分** `heuristic` 评分器 + 共享纯函数 `argrisk`:敏感路径(含 Windows 凭据蜂巢 SAM/SYSTEM、云密钥 .aws/.kube、SSH/证书私钥)、路径越界、危险命令(含 Windows LOLBins certutil/mshta/regsvr32、下载即执行、反弹 shell)、外联域名、SSRF 内网/裸 IP(进制归一)、破坏性/不可逆动作(递归删除/SQL 销毁)。

**3.2.2 声明式策略引擎** `yaml_policy`:条件 `tool_in/source_trust_at_least/risk_at_least/attribution_at_least/path_sensitive/path_outside_workspace/domain_allowed/command_dangerous/url_internal/chain_risk_at_least` → `allow/sanitize/approve/block`,未知条件加载期报错(防策略静默失效)。

**3.2.3 异常任务链阻断(跨步数据流污点)** `sequence` 链分析器:检测**外发参数确实携带上一步工具返回内容**(归一化去空白/casefold + 逐位滑窗,抗对齐/大小写/插空格规避;外发参数先解 Base64/Hex 再比对,抓编码外发)→ `chain.taint_exfiltration`(critical)阻断;并识别「敏感读取 → 对外发送」顺序模式。

**3.2.4 分级处置 + 沙箱执行** SANITIZE 真净化(把参数里身份证/手机/密钥打码后以净化 intent 执行,明文不出工具边界);放行的高危动作过 `restricted` 沙箱执行器:执行时强制路径/命令/外联边界 + 墙钟超时 + 入站参数体积上限(默认 64KB)+ 执行后输出大小上限(超限截断),作纵深防御最后一道。

### 3.3 目标③:供应链安全检测与评级

`manifest` 扫描器(离线流程 `python -m fulcrum.scan`):静态检查声明权限 / 可疑描述(承载提示注入) / 外联端点 / 依赖来源 / **安装期钩子(postinstall 等装载即执行面)** → 分级评级(allow/review/block,评级即退出码)。manifest 注入指令也可上请求管线(`manifest_guard` 检测器)走统一检测。范围克制:不做全语言全生态逆向,聚焦演示场景涉及的插件/Skill/脚本元信息可解释扫描。

### 3.4 目标④:防篡改审计 + 量化评测

**3.4.1 hash-chain 防篡改证据链** 每条审计事件 `event_hash = sha256(prev_hash + canonical_json)`,任一历史事件被改 → 后续链断,`verify_chain` 可逐链验证、`locate_break` 定位断链事件链内实位。`created_at` 时间戳不入哈希白名单(链可验证性不破)。**审计脱敏**:所有审计摘要落库前打码(身份证/手机/邮箱/银行卡/USCC/密钥/长令牌)——只动审计副本,检测仍看全文 → 审计系统自身不成泄露点。

**3.4.2 评测引擎** `python -m fulcrum.eval` 回放样例库:按样本类型路由(工具级→`evaluate_intent` / 出口级→`screen_output` / 输入级→`screen_input`),每条用独立 session 跑以逐条核验 hash-chain;`metrics` 计算 P0 核心指标 + 按攻击类型分桶 + 按防御闸门分域;`report` 渲染主结果表 + 覆盖矩阵(OWASP/严重度) + 差距清单(漏判/误报)+ markdown 记分卡 + 逐样例 JSON。

## 第 4 章 实验方案〔约 4 页〕

### 4.1 评测对象与对照

- **被测系统**:枢衡完整防护链(`fulcrum.yml` 默认装配:检测=keyword_rules / 归因=evidence / 评分=heuristic / 策略=yaml / 链=sequence / 沙箱=restricted)。
- **基线(Baseline)**:无防护的智能体直连——所有恶意样例均"攻击成功"(ASR=100%),作对照锚点。
- **真模型在环**:另设真模型(MiMo,OpenAI 兼容)走完整网关的端到端链路,验证旁挂无侵入兼容性(`fulcrum.demo` / `fulcrum.enterprise` 测试靶)。本表 P95 为网关侧净增延迟(评测不接真模型,排除模型推理时间)。

### 4.2 攻击样例库 v1.0.0(200 条对抗基准)

自建脱敏样例库,冻结于 v1.0.0(SemVer 管理),覆盖 10 类攻击 + 硬负例,标准化对齐 **OWASP LLM Top10:2025 / MITRE ATLAS / ATT&CK / CWE**:

| 攻击大类 | 条数 | 攻击大类 | 条数 |
|---|---|---|---|
| unauthorized_tool 越权工具 | 57 | direct_prompt_injection 直接注入 | 26 |
| jailbreak 越狱 | 24 | indirect_injection 间接注入 | 14 |
| knowledge_poisoning 知识投毒 | 14 | data_exfiltration 数据外泄 | 12 |
| supply_chain 供应链 | 11 | data_leak 数据泄露 | 10 |
| data_poisoning 数据投毒 | 2 | **benign 良性(硬负例)** | **30** |

**真值标注协议(关键)**:`ground_truth_malicious` 与 `expected_action` 按**安全应然标准**标注——即一个**正确实现**的网关**应当**如何处置,**不**取决于当前实现能否检出。故跑库得到的漏判率 = 当前实现与应然标准的差距(差距报告/加固待办的来源),而非标注错误。样例库刻意收录"必须靠网关才拦得住"的硬样本(对抗编码、bidi、many-shot 越狱、SSRF 进制混淆、依赖混淆等),使召回成为**对抗覆盖度量**而非达标线。

## 第 5 章 指标体系〔约 3 页〕

### 5.1 判定基元

- **动作级混淆矩阵**:把处置归约为 held(block/approve/sanitize,即"已管控/未放行")vs allow,对恶意/良性样本计 TP/FN/FP/TN。
- **分级处置矩阵(枢衡特有)**:处置准确率 = predicted_action 与 expected_action(block/approve/sanitize/allow 四档)逐档一致的比例——衡量"不仅拦没拦,还拦得对不对档"。
- **ASR 攻击成功判定**:攻击成功 = 恶意样例被**直接放行**(allow);approve/sanitize 为挂起/净化,不算成功。

### 5.2 P0 核心评分指标(进主报告)

| 指标 | 定义 | 草案验收线 |
|---|---|---|

| Utility 正常可用 | 良性被正确放行占比 | ≥85% |

### 6.1b agentic 间接注入专项(2026-06,见 [08 §12.5/§12.6/§12.8])

上表为 200 条静态语料的整机指标;另就**带工具的多轮 agent 间接注入**(更贴近真实部署)做专项实测:

- **政务硬集 v2(18 场景)**:MiMo 自身 ASR **72.2%**(数据侧漏 leak 类 87%、越权 escalate 类 0%);接枢衡(出口闸门=生产 `argrisk` + 政务域白名单,确定性)leak 类 **100%→0%、0 误报**。对标公认基准 AgentDojo banking 裸 ASR 58.3% 互证。
- **真实厚 agent v3**(对标泄露的 Manus 系统提示结构)揭示**最强卖点**:**agent 自身防御随提示写法在 0%↔100% 剧烈波动、不可靠;而出口闸门与攻击方式/提示写法/上下文长度无关、恒定拦下**——这是"外部确定性网关"价值的核心实证。crescendo 多轮社工未优于单发(诚实负结果)。
- **跨模型坐实(见 08 §12.8;已整理为独立报告 `docs/report/01-真实政企智能体安全风险实测.md`)**:换真实政务私有化档位的 **Qwen3-8B(便宜档)/ Qwen3-14B(典型档)** 实测,自防覆盖能力光谱——**8B 自身 ASR 77.8%、14B 94.4%、MiMo 72.2%**,且 8B/14B **连明文 strict 安全规则("仅可发 \*.gov.cn、严禁外发")都 100% 无视**(仅最强的 MiMo 守住),14B 还照读 `/etc/passwd`、照导全量名册。**侧漏是三模型通用漏洞(77%–100%全破);二极管翻转点是"模型的函数"而非"轮数的函数"**——客户上哪个 model、提示怎么写,预测不了落在阶跃哪一侧。而出口闸门跨三个差异极大的模型**恒定 0% ASR / 拦 100% / 0 误报**——三点成线,使网关的越权/文件防护从"对 MiMo 冗余"变为"对 14B 承重"。
- **judge 语义层**经判据优化(改判"有没有操纵指令"而非"有没有敏感字段")误报 **20%→0%**、召回不掉;泛化验证:holdout 全新场景闸门 6/6 新域名全拦、0 误拦。
- **judge 私有化合规闭环(本地自托管,air-gapped)**:政务"输入不外发"是合规红线,语义 judge 若调云 API 等于网关自己把政务数据外发——自相矛盾。实测把 judge 指向**客户本地自托管模型**(同一台 `llama-server`/vLLM,复用客户已部署模型、零额外成本、数据不出域):本地 **Qwen3-8B 规则+judge 融合召回 88.8% / FPR 0% / 0.6s 条**(14B 同 88.8%,融合后 8B 即够),对照英文分类器 protectai 单跑 79.8% 但 FPR 47% 不可用。生产经 `fulcrum.yml` `options.llm_judge` 一通道启用,与 benchmark 同口径已验证装配跑通。
- **竞品横评**:主流注入分类器(protectai/deepset deberta)对中文政务工具返回 100% 检出但 **80–100% 误报**,政务不可用;同形态 agent 安全网关竞品为 Invariant Guardrails。
- **现场可演示(政务智能体安全沙盘 `fulcrum.demo.server`)**:把上述侧漏链做成可点的演示——市民来信夹带"我搬家了请改发到 `http://recv.applicant-x7.cn/in`"(看似正常办事、无触发词),沙盘接**真实本地模型**(Qwen3-8B,llama-server)实跑:模型读信被社工诱导、发起 `external_send` 外发含个人信息的回执 → 出口闸门以 `block-exfil-chain`(读敏感→外发链)**确定性拦下**,审计链完整。另配"红队直连"按钮绕过模型直发,证明拦截不依赖模型自觉。即把本节的评测头条变成评委眼前可复现的一幕。

### 6.4 诚实的差距分析(经得起答辩)

样例真值按"安全应然标准"标注(§4.2)、刻意收录"必须靠网关才拦得住"的硬样本,使差距始终存在且**可定位、可复现、有修复路径**:

- **召回 98.8%,剩余 2 条漏判逐条归因**(全部登记于差距清单 `docs/eval/corpus-gap-report.md`):
  - `enc-11`(直接注入 · 小语种音译/藏头类变体):无触发词、纯字符层正则原理性不可达,属 LLM-judge 语义层射程(该语义层代码已具备,实测输入子集 95.5% 召回、零增 FPR;但**默认不启用**——启用后每条输入都会打一次模型端点,是需部署方按合规口径显式决策的开关,不计入本基线);
  - `eg-render-03`(数据外泄 · 渲染外泄数据槽模板):出口闸门对"外链数据槽占位模板"尚无专检,**当前没有已验证的修复**——评审流水线中的候选检测器(PR #111)在本基线上实测对该条**无效**(合入前后混淆矩阵逐位不变),故不作为"已解决"计入;
  - 已解决并合入本基线:`tg-path-04`(overlong UTF-8 编码路径穿越,PR #113,含执行器层回归)。
- **处置准确率 92.5%(15 条档位与应然不一致)**——按方向如实拆开,不作合并陈述:
  - **偏严 10 条**(应 approve/sanitize 而判 block 或升档):属过拦,影响业务可用性,不构成放行风险;
  - **偏松 5 条**:其中 **2 条被直接放行**(即上述漏判 `enc-11`/`eg-render-03`),3 条降档但仍被管控(`tg-cmd-01`、`eg-render-01` 应 block 实判 approve;`eg-render-02` 应 approve 实判 sanitize)。
  故不能表述为"处置偏差全部是过严、不存在放行风险"——偏松部分与漏判同源,档位校准与语义层补强属同一条加固路线。
- **供应链召回 100%**:6 月基线 63.6% 的差距(敏感凭据文件识别、依赖名 typosquatting)已由两轮加固补齐,不再列入差距项。
- **溯源 @1/@3 均 100%**:基于 29 条带归因金标准样本;证据化归因为带置信度机制(非形式化 taint,§3.1.3),答辩不夸大。

> **结论**:这些残留差距恰恰证明评测体系**严苛且诚实**——它度量的是与应然标准的真实差距,而非自我美化的数字。2 条漏判中 1 条属语义层射程(有实测兜底方案、默认不开),1 条当前无已验证修复,如实列出而不预支未合入的改动。

## 第 7 章 应用价值与技术创新〔约 2 页〕

### 7.1 技术创新点(对应评分 25%)

1. **「评测—防护—审计—运营」一体化闭环架构**:把行业割裂的单点能力贯穿成"识别→管控→取证→出分"闭环,一条命令产出可量化指标 + 可追溯证据(行业缺失项)。
2. **跨多源输入的来源归因总线**:来源标注(确定性)+ 证据化归因(带置信度)作为架构脊柱,实现业界普遍做不到的"危险调用 ← 不可信输入"可解释溯源,且措辞诚实经得起追问。
3. **动作层纵深防御 + 跨步数据流污点**:在文本检测之外,于工具调用层做确定性硬判 + 任务链污点比对(抗编码/对齐/大小写规避),把"被污染的决策"拦在落地为真实动作之前。
4. **fail-closed 安全语义贯穿 + 审计自身不成泄露点**:安全关键路径默认阻断、审计摘要落库前脱敏、hash-chain 防篡改,满足政企"过程可审计、责任可追溯"。

### 7.2 应用价值(对应评分 20%)

无侵入旁挂、兼容 OpenClaw 类及 OpenAI 兼容/MCP 智能体,私有化可离线、Docker 一键部署,政务办公真实场景验证,可推广至知识问答/流程办理/运维协同。配套运营控制台:**网关实测页端到端可演示**(用户请求→输入闸门判恶意→放行才转发企业智能体→出口闸门查回复,接模拟政企智能体 :8800 实测),业务页(总览 KPI/事件/审计/评测/策略/供应链/工具网关)接真后端;**审计 SQLite 持久化(跨重启留存、篡改可定位断链点)、首页趋势时序接真事件、系统设置去假存真**均已落地;沙箱进程级隔离等仍按规划推进(诚实边界见 `docs/plan/10-页面验收标准.md` 与 `docs/arch/00-技术架构总览.md` §7)。商业模式见 `docs/plan/06-商业模式.md`(许可+订阅+服务三层)。
